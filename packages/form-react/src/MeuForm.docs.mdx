# Form

## 当前能力

- `MeuForm` 使用原生 `form`，通过 React Hook Form `FormProvider` 向 Meu adapter 提供统一作用域。
- `useMeuForm` 支持 React Hook Form 原生 resolver，或使用单一 Zod schema；两者在类型上互斥。
- Zod transform 的输入值与提交值可通过三个泛型分别表达，不再把 transform 后的类型伪装成输入类型。
- 表单级 `disabled` 会传播到本批次覆盖的文本、选择、数值与分段控件 adapter。
- adapter 的局部 `disabled` 会同步登记到 React Hook Form：禁用期间既不进入 RHF `onSubmit`，也不进入原生 `FormData`；重新启用后保留值并恢复提交。
- Calendar 将整个月历视为一个复合字段：日期按钮和月份控件之间移动焦点不会提前 touched，只有焦点离开整个月历时才触发 RHF blur 与 `mode="onBlur"` 校验。
- adapter 将 `required` 同步给 Field 和适用的原生控件；`MeuForm` 默认 `noValidate=true`，由 React Hook Form 负责验证与错误展示。
- adapter 的错误视觉取 RHF `fieldState.invalid` 与调用方显式 `status="error"` 的并集；字段当前通过 RHF 校验时，不会把业务仍需展示的错误态重置为 default。
- NumberKeyboard、PasscodeInput、Picker、CascadePicker、DatePicker、DateRangePicker、Calendar、TimePicker、TreeSelect 与 ImageUploader 都提供明确的原生 FormData 契约；集合值按同名重复条目保持顺序。
- 服务端错误辅助函数从 `@meu/form-react/server` 导入，并按所属 `MeuForm` 内的 DOM 顺序聚焦首个已注册错误字段；同页多表单的同名字段不会互相干扰。
- `MeuForm` 透传原生 form 属性，`ref` 指向真实 `HTMLFormElement`。
- 原生 reset 会先调用消费方 `onReset`；事件未被阻止时，再同步重置 RHF 的值、dirty、touched 与 error 状态。
- 条件字段默认在卸载时注销，使 RHF 提交与原生 successful controls 一致；连续异步校验保留最新字段结果。
- 重复原生 submit 默认在当前提交 Promise 完成前忽略；拒绝可由 `onSubmitError` 明确接收。
- 客户端与服务端错误均按所属表单内的 DOM 顺序聚焦首个可用字段；新一批服务端错误默认替换上一批 server error。

当前状态为 V2 `verification`。22 个 adapter 的 touched、ref、required 与适用 readOnly 参数化矩阵，以及复杂 Picker、日期、树与上传值的 FormData、移动 E2E 和浏览器集成证据已建立；真机输入法与读屏证明尚未完成，因此不能标记为 commercial。

## 何时使用

用于需要 React Hook Form 生命周期、Zod 校验、服务端错误映射、嵌套字段或数组字段的移动 H5 表单。简单的浏览器提交可以直接组合原生 `form`、Field 和 Meu 输入组件，不必引入该包。

## 何时不要使用

- 不把请求、缓存、路由、Toast 或业务状态放入 MeuForm。
- 不通过 `@meu/form-react` 间接导入 React Hook Form。上游 hooks 和类型应直接从 `react-hook-form` 导入。
- 不假设 RHF 中存在的任意对象会自动进入 `new FormData(form)`；复杂 adapter 只提交文档定义的安全标量，并允许通过同步 `serializeValue` 显式改写后端契约。

## 结构与状态

结构为原生 `form`、`FormProvider` 和各字段 adapter。字段的 default、focus、invalid、disabled、readOnly、loading 状态由底层组件渲染。Form 本身不增加卡片、间距或状态动画。

## 基础用法

```tsx
"use client";

import { MeuForm, MeuFormTextInput, useMeuForm } from "@meu/form-react";

type Values = { storeName: string };

export function StoreForm() {
  const form = useMeuForm<Values>({ defaultValues: { storeName: "" } });

  return (
    <MeuForm form={form} onSubmit={(values) => saveStore(values)}>
      <MeuFormTextInput<Values>
        name="storeName"
        label="店铺名称"
        required
        rules={{ required: "请输入店铺名称" }}
      />
      <button type="submit">保存更改</button>
    </MeuForm>
  );
}
```

## 受控与非受控

由 React Hook Form 管理。`defaultValues` 是推荐事实源；不要同时向 adapter 传 `value/defaultValue`。业务需要受控外部同步时使用 RHF `values`，需要建立新的 dirty 基线时使用 `reset(nextValues)`，局部更新使用 `setValue`，订阅使用 `useWatch`。`values` 更新可能按 RHF `resetOptions` 重置 dirty/touched/errors，调用方必须显式选择保留策略。

## 表单集成

- 文本、textarea、search、checkbox、switch、stepper、slider 和 rate 保留原生 `name/ref/onBlur/required/disabled`。
- `MeuFormSlider readOnly` 使用底层 Slider 的 meter + hidden input 契约：不可调值、仍进入 FormData，ref 指向 hidden input；disabled readOnly 仍会从 RHF 与原生提交中省略。
- CheckboxGroup、RadioGroup、Selector 与 SegmentedControl 只有在焦点离开整个复合控件后才调用 RHF `onBlur`，组内移动焦点不会提前变成 touched。
- `MeuFormSegmentedControl` 固定使用原生 `radiogroup` 模式，以保留 `name`、`required`、FormData 和 RHF 字段契约；导航型 `mode="tabs"` 不属于表单字段，请直接使用 `SegmentedControl` 并由页面拥有对应 tabpanel。
- Calendar 同样只在焦点离开整个复合根时调用 RHF 与消费方 `onBlur`；RHF 先更新 touched，再调用消费方回调。选择日期只更新 value/dirty，不把 change 伪装成 blur。
- 非原生字符串/标量集合通过 hidden successful controls 参与 FormData；`getAll(name)` 按选择顺序返回 Picker、CascadePicker、TreeSelect、日期范围、Calendar 集合与已完成上传 URL。
- 无论 `disabled` 来自 adapter 自身、Picker trigger 还是 NumberKeyboard 键盘/trigger，禁用字段都会同时从 RHF 提交值和原生 successful controls 中省略；不要把 `disabled` 当作仅视觉状态。`readOnly` 字段仍保留提交值。
- `rules.required` 决定 RHF 校验；视觉 `required` 同时表达字段必填并下传原生语义。二者需要由调用方保持一致。
- 默认 `noValidate=true`，避免浏览器气泡与 React Hook Form 错误重复。显式设置 `noValidate={false}` 会启用浏览器原生约束阻断。
- `useMeuForm` 默认 `shouldUnregister=true`，条件卸载字段不会继续进入 RHF values/submit；确需保存分步表单的离屏值时显式传 `shouldUnregister=false`。
- 原生 `FormData` 只包含当前 DOM 中有 name 且未禁用的 successful controls；readOnly 仍提交，disabled 与已卸载字段省略，同名 hidden controls 通过 `getAll(name)` 保持数组顺序。

### Adapter 商用契约矩阵

| 分类            | Adapter                                                                                    | touched 契约                                                       | RHF ref 目标                                                          | required 契约                                                                                | readOnly 契约                                                                   |
| --------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ | --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| native input    | TextInput、TextArea、SearchField、Checkbox、Switch、Stepper、Slider、Rate、PasscodeInput   | 原生输入失焦后 touched                                             | 对应 native input；Slider/Rate 只读态的 hidden input 不用于命令式聚焦 | 9/9 下传原生 required                                                                        | 9/9 支持；冻结修改但保留 successful control/FormData                            |
| group           | CheckboxGroup、RadioGroup、Selector、SegmentedControl                                      | 仅焦点离开整组后 touched，组内移焦不提前触发                       | CheckboxGroup/RadioGroup 为可聚焦 group 根；其余为底层注册目标        | RadioGroup、Selector、SegmentedControl 下传原生 required；CheckboxGroup 使用可访问“必填”说明 | CheckboxGroup、RadioGroup、Selector 支持；SegmentedControl 未定义 readOnly      |
| overlay trigger | Picker、CascadePicker、DatePicker、DateRangePicker、TimePicker、TreeSelect、NumberKeyboard | 关闭态 trigger 失焦，或一次已打开交互的确认/取消/关闭后 touched    | 原生 trigger button                                                   | trigger 通过 `aria-describedby` 关联可访问“必填”说明                                         | 仅 TreeSelect 支持，并保留可查看、可提交但不可确认改值；其余六项未定义 readOnly |
| complex value   | Calendar、ImageUploader                                                                    | Calendar 离开整个复合根后 touched；Uploader 失焦或值变化后 touched | Calendar 的当前日期按钮；Uploader 的真实 file input                   | 复合控件通过 `aria-describedby` 关联可访问“必填”说明                                         | ImageUploader 支持，已完成 URL 仍由 hidden input 提交；Calendar 未定义 readOnly |

矩阵中的“未定义 readOnly”表示公开底层控件没有该状态，adapter 不模拟只读。需要只展示既有值时应使用对应展示组件；需要从提交中排除时使用 `disabled`，两者不要混用。22 个 adapter 都有参数化 touched/ref/required 证据；readOnly 证据只统计真实支持该能力的 14 个 adapter，另外 8 个明确冻结为不支持清单。

## Props

`MeuFormProps` 继承原生 form 属性，但以经过 RHF 校验的 `action` 与 `onSubmit` 契约替代原生同名属性，并要求 `form` 与类型安全的 RHF `onSubmit`。`action`、`onInvalid`、`onSubmitError`、`shouldFocusError`、`submitConcurrency`、`noValidate` 和 `ref` 为主要表单级能力。`submitConcurrency` 默认 `ignore`，可显式设为 `allow` 允许并行提交。adapter 的 Props 表由 API Extractor 从各公开类型生成。

`useMeuForm` 接受 React Hook Form 配置，并在 `schema` 与 `resolver` 中二选一。字段 adapter 使用 `MeuStringFieldPath`、`MeuBooleanFieldPath`、`MeuNumberFieldPath`、`MeuSelectionFieldPath` 与 `MeuCollectionFieldPath` 阻止明显的错误值形状绑定；日期范围与时间分别公开 `MeuDateRangePickerFieldPath`、`MeuTimePickerFieldPath`，避免公开 Props 引用不可导入的内部别名。

## Events

- `onSubmit(values, event)`：校验通过后触发；Zod transform 存在时 values 是 transform 后类型。
- `onInvalid(errors, event)`：RHF 校验未通过时触发。
- `onSubmitError(error)`：接收 `onSubmit` 或异步 `onInvalid` 的 rejection；省略时错误会在异步任务中重新抛出，避免静默失败。
- adapter 的 `onChange/onBlur`：先更新 RHF value/touched，再调用消费方同名回调；业务回调读取 `getValues()` 时已得到新值。
- adapter 的显式 `status="error"` 只控制呈现和 `aria-invalid`，不会凭空创建 RHF error；需要阻止提交时仍应配置 `rules`、schema 或服务端错误。
- 原生 `onReset` 先交给消费方；未调用 `preventDefault()` 时，`MeuForm` 会同步执行 `form.reset()`。`onInput/onChange` 等其余 form 事件继续透传。
- `applyMeuFormErrors(form, errors, options)`：默认先清除该 form 上一批由本 helper 写入的 server error，再写入新响应；按所属表单的 DOM 顺序跳过 disabled/inert/aria-hidden 字段并聚焦首个可用具名控件。`clearPrevious=false` 可合并响应，`shouldFocusFirst=false` 可禁止聚焦。未由 `MeuForm` 承载的裸 RHF 实例保持 document fallback。

## Ref 与命令式方法

`MeuForm` ref 指向 `HTMLFormElement`，可使用 `requestSubmit()`、`reset()` 和原生查询。字段聚焦优先使用 RHF `setFocus()`；所有官方 adapter 会在 Field 根暴露内部诊断属性 `data-meu-form-field`，用于稳定计算复合控件与空值控件的 DOM 顺序，但业务样式和逻辑不得依赖它。

## 键盘操作

| 按键            | 行为                                                 |
| --------------- | ---------------------------------------------------- |
| Tab / Shift+Tab | 按 DOM 顺序移动，复合组内部遵循底层控件原生行为      |
| Enter           | 单行字段遵循浏览器 submit 规则；SearchField 另有契约 |
| Space           | 切换 checkbox、switch 或当前可操作按钮               |

首次错误聚焦默认由 MeuForm 在错误提交后按 DOM 顺序执行；`useMeuForm` 因此默认关闭 RHF 自己的注册顺序聚焦。直接传入裸 `useForm()` 实例时建议设置 `shouldFocusError:false`，避免两套聚焦策略竞争。

## 触摸与手势

Form 不定义手势。所有 adapter 继承底层组件至少 44×44 CSS px 的触控目标、pointer cancel 和滚动冲突策略。`submitConcurrency="ignore"` 在 Promise 完成前阻止重复原生提交；业务仍应使用 `formState.isSubmitting` 呈现 loading 和禁用状态。

## 无障碍

使用原生 form、input、textarea、button、checkbox、radio 与 range 语义。Field 负责 label、description、error、required 和 invalid 关联；复合 adapter 使用 group/radiogroup 名称。服务端错误写入后应公告对应 alert，并把焦点移到页面顺序中的首个错误控件。

## 动效

Form 不定义动效。字段和反馈组件各自遵守 ConfigProvider motion 与 `prefers-reduced-motion`。校验错误不得通过长位移动画导致输入位置跳动。

## 主题与定制

Form 不创建视觉容器。布局、间距、Field 和底层控件使用 Meu Token；`className`、`style` 和原生 form 属性由 `MeuForm` 透传。

## SSR 与 Next.js

`@meu/form-react` 主入口是 Client Component 边界。纯服务端错误类型和辅助函数从 `@meu/form-react/server` 导入，避免穿过带有 `"use client"` 的根入口。默认值必须在服务端数据与首次客户端渲染之间稳定。

RHF 的异步 `handleSubmit` 必须先阻止浏览器默认提交，因此 MeuForm 在客户端校验及 `onSubmit` 成功后显式执行 `action`：React 19/Next function action 收到所属 document 构造的 native `FormData`（包含同名多值和原始 submitter），字符串 action 通过带原始 submitter 的 `requestSubmit()` 继续原生提交。action rejection 进入 `onSubmitError`；iframe/多 document 场景不会错误依赖顶层 window 的 DOM 构造器。

这是 client-mediated action 边界，不等同于浏览器在 hydration 前的 progressive enhancement，也不建立 React 原生 action 的 `useFormStatus` pending 上下文。必须依赖这两项能力时使用独立原生 form；使用 MeuForm 时以 `formState.isSubmitting` 展示 pending，并用 `applyMeuFormErrors` 映射 action 返回的结构化字段错误。

## RTL 与国际化

Form 不生成文案。Field、组件默认 label、日期格式和错误消息分别由 ConfigProvider、adapter 或业务提供。服务端错误必须使用当前 locale，且中英文长文案需在 200% 字号下测试。

## 浏览器与 WebView

核心依赖原生 form 和 React Hook Form。隔离 Next H5 消费端会在 Pixel 5 mobile Chromium 与 iPhone 13 mobile WebKit 项目中运行；现有断言覆盖提交、客户端校验、清除、复杂值确认/取消、部分原生序列化、图片字段错误聚焦、原生 reset，以及服务端错误按 DOM 顺序聚焦并滚入可视区域。软键盘、自动填充、密码管理和 IME 仍需真机验证。

## 边界情况与已知限制

- DatePicker 默认按 active adapter 与 `precision` 输出一个值；DateRangePicker 与 Calendar 默认输出同名重复 `YYYY-MM-DD`，ImageUploader 默认输出同名重复的已完成 URL，瞬态原始 File 不提交。
- `serializeValue` 可返回一个安全标量、同名重复标量或显式 JSON；它必须同步。抛错、对象和 Promise 结果都会省略该字段，避免 `[object Object]` 与未处理拒绝。`null`、`undefined`、空集合、无效日期和 disabled 同样不进入 FormData。
- overlay adapter 在打开并把焦点移入 Portal 时保持 untouched；确认、取消、遮罩或 Escape 关闭时才标记 touched。受控模式拒绝打开不会触碰字段，拒绝关闭仍会记录已经发生的用户交互。
- 仅设置 `required` 不会自动生成 RHF `rules.required`；自动合成会改变校验消息和现有行为，因此当前不隐式处理。
- 从根入口移除了 React Hook Form wildcard re-export；消费者必须直接依赖并导入 `react-hook-form`。
- 默认卸载即注销；多步骤表单若通过条件卸载保存离屏步骤值，升级时需显式设置 `shouldUnregister:false`。
- `action` 现在在 RHF 校验与 `onSubmit` 成功后执行；此前虽然类型继承但会被 `preventDefault` 静默截断。依赖原生 progressive enhancement/`useFormStatus` 的页面仍应使用原生 form。

## 性能预算

Form 不应在每次按键时遍历整棵 DOM。只有客户端提交失败或应用服务端错误时，才在所属 form 内按需扫描 adapter 标记与具名控件，确定首个错误顺序。adapter 不复制业务值，也不增加全局事件监听。

## V2 优化记录

### 待优化

- 冻结复杂值 serializer 的后端版本迁移策略，并在真实业务接入时记录服务端解析样例。
- 补 Chromatic Light/Dark 与真机输入记录。

### 已完成

- 表单级 disabled 和 required 传播到高频文本、选择与数值 adapter。
- 复合控件仅在焦点离开整个组后标记 touched。
- Zod input/output transform 类型进入公开 API，schema 与 resolver 类型互斥。
- 公开日期范围与时间字段路径类型，API 报告不再包含 forgotten export。
- 新增 server-safe 子路径，移除 React Hook Form wildcard 公共面，排除 Story declarations，并声明 tree-shaking side effects。
- 服务端错误首次聚焦按 DOM 顺序执行；MeuForm 支持原生 form ref。
- NumberKeyboard、PasscodeInput、Picker、CascadePicker、DatePicker、DateRangePicker、Calendar、TimePicker、TreeSelect 与 ImageUploader 已进入原生 FormData；复杂集合使用同名重复条目，调用方也可显式序列化为 JSON。
- 22 个 adapter 已按 native input、group、overlay trigger 与 complex value 分类，参数化冻结 touched、RHF ref、required，以及 14 个适用 adapter 的 readOnly/FormData 契约；其余 8 个明确记录为未定义 readOnly。
- Figma `Meu/MeuForm` 已补齐 Idle、FirstError、Submitting、Success、ServerError replace/merge 与 DynamicFieldRemoved 视觉状态，验证 Light/Dark Token、AA 对比度、44px 目标和无布局缺陷。
