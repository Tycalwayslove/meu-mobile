# Progress

## 当前能力

- 支持 determinate 与 indeterminate；确定值将非有限数归零并夹紧到 0–100。
- 支持三档厚度、四种 tone、可见标签/数值、`formatValue`、`valueText` 与显式 `announce`。
- 使用 `role="progressbar"`；不确定状态省略 `aria-valuenow`，reduced-motion 下停止循环动画。

当前为 `verification`：Unit、SSR、Story interaction、本地 axe 与全库移动 WebKit/Chromium 门禁已建立；最终 Chromatic 与真机读屏尚无证据。

## 何时使用

用于上传、同步、批处理等有持续时间的任务。能计算完成百分比时使用 determinate；不能计算时使用 indeterminate。

## 何时不要使用

不要用于静态评分、容量或业务指标；使用 Rate、meter 或数据展示。瞬时操作不要闪现进度条。

## 结构与状态

根 progressbar 包含可选 header 和装饰性 track/fill。根暴露 `data-size`、`data-tone`、`data-state=determinate|indeterminate`；内部 class 非公开 API。

## 基础用法

```tsx
<Progress label="上传资料" value={64} showValue valueText="已上传百分之六十四" />
```

## 受控与非受控

不适用。Progress 是只读派生视图，每次渲染完全服从 `value`/`indeterminate`。

## 表单集成

不适用。组件不提交 FormData，不代表表单字段；任务状态由业务层拥有。

## Props

`value` 固定表示百分比；`formatValue` 只改变可见内容，`valueText` 改变读屏值文本。`announce` 默认 false，避免高频更新制造 live-region 噪声。tone 不能作为唯一状态信息。

## Events

不适用。组件不发出完成事件；完成判断与副作用属于调用方。

## Ref 与命令式方法

`ref` 指向根 `HTMLDivElement`；无命令式方法。

## 键盘操作

| 按键   | 行为                               |
| ------ | ---------------------------------- |
| 不适用 | Progress 不可交互、不进入 Tab 顺序 |

## 触摸与手势

不适用；不得让用户拖动 fill。需要输入时使用 Slider。

## 无障碍

- accessible name 优先 `aria-label`，其次字符串 `label`，否则使用 locale fallback。
- determinate 暴露 0/100 bounds 和夹紧后的 `aria-valuenow`；indeterminate 不暴露当前值。
- 仅在更新频率低且确需公告时启用 `announce`；高频任务应由业务按阶段公告。

## 动效

determinate 使用 transform 过渡，indeterminate 使用循环位移动画。`prefers-reduced-motion: reduce` 下循环停止、过渡缩至 1ms；`ConfigProvider motion="reduced"` 同样停止循环并将过渡降为 0ms。

## 主题与定制

使用公共颜色、圆角、间距与 motion Token。稳定属性为 `data-meu-component`、`data-size`、`data-state`、`data-tone`。

## SSR 与 Next.js

无浏览器全局读取，SSR 输出确定；组件带 `use client` 以读取 ConfigProvider locale。首屏服务端和客户端必须传同一 locale/value。

## RTL 与国际化

RTL 下确定进度从逻辑起点（右侧）增长。可见格式和 `valueText` 由业务负责 locale 数字与语序。

## 浏览器与 WebView

依赖基础 flex/grid、transform、CSS 自定义属性；forced-colors 使用系统 Highlight。未声明真机 WebView 验证。

## 边界情况与已知限制

固定范围 0–100；不支持分段、圆环、缓冲进度或自动节流公告。NaN/Infinity 视为 0。

## 性能预算

每实例常数 DOM；只动画 transform。高频进度应由调用方限频，避免每帧 React 渲染。

## 测试证据

- Unit: 5 项，覆盖 clamp、indeterminate、格式化、locale、announcement/valueText，以及显式 live-region 属性优先级。
- Story interaction: `ClampedAndFormatted.play` 验证只读 progressbar 的边界值和可访问值文本；`check-storybook-links` 本地验证 play-fn 为 81/81（按 Storybook title 计）。
- Storybook 浏览器矩阵：本地扫描器在 390×844 视口验证 444 个 Story × 7 场景（Light、Dark、en-US、RTL、reduced-motion、200% 字体、forced-colors），共 3,108 个组合；有 play 的 Story 必须先返回 `storyFinished=success`，再运行 axe WCAG A/AA，结果为 0 违规、0 `pageerror`。
- 官网 Next 运行时：本地 production build 在 390×844 下逐页验证 68 个组件页的 Light/Dark（136 场景）；主题恢复、H1/预览/API 结构、React `pageerror` / `console.error`（含 hydration mismatch）和 axe WCAG A/AA 均通过。
- Bundle：Rollup tree-shaken ESM（React 与包 peer dependencies external）单一公开值 gzip 2310 B / 32768 B 预算，组合 Brotli 2035 B；共享样式由应用单独导入一次。
- SSR/hydration: Node SSR 1 项；隔离 Next 16 hydration 后 determinate 值与 accessible value 保持一致，0 hydration/runtime error。
- RTL: 双移动引擎在 `dir="rtl"` Provider 下验证 indeterminate fill 使用逻辑右侧 transform origin。
- Reduced motion: 双移动引擎验证 `motion="reduced"` 会将 indeterminate `animation-name` 置为 none，并把 transition-duration 降为 0s。
- Mobile Chromium/WebKit E2E: 反馈场景在两种引擎断言 `progressbar` 名称、`aria-valuenow=64`、低频 polite/atomic 公告与 `aria-valuetext`，外部推进后同步更新为 76；另覆盖 RTL + reduced-motion 的 indeterminate 语义和计算样式。
- Chromatic Light/Dark: 未执行。
- Real device: 未执行。
