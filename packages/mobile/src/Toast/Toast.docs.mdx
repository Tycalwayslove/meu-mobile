# Toast

## 当前能力

- 声明式受控/非受控 Toast 与 scoped `ToastProvider/useToast` FIFO 队列；同一 id 原位完整替换配置。
- neutral/success polite status，warning/danger assertive alert；action 在 live region 外且不会移动焦点。
- 默认 3s、action 至少 5s、duration=0 常驻；hover、focus、页面隐藏和 async action 暂停，false/reject 保持打开。
- Portal 继承 ConfigProvider container、locale、dir、theme、motion；支持 safe area、RTL、reduced-motion、forced-colors。
- provider/controller 支持 show/success/warning/danger/update/close/clear；默认最多保留 20 条记录，关闭原因完整且卸载回收 timer。
- Provider 将视觉消息与 live announcer 分离：画面始终即时更新，连续公告每 500ms 最多发布一次最新值；polite 升级为 assertive 时立即公告。

## 何时使用

用于短暂、非阻断、无需用户立即确认的操作反馈。重要失败可以提供一个短重试或撤销 action。

## 何时不要使用

需要确认、输入、长说明或不可逆后果时用 Dialog/BottomSheet；字段错误用 Field；持续后台任务用 Progress/状态页。

## 结构与状态

Portal viewport 不接管 pointer；内部 toast 包含 tone marker、icon、live message 和可选原生 action。Provider 只渲染队首，队首 exit 后先进先出。visible、queued 和尚在退场的记录总数受 `maxToasts` 限制。

## 基础用法

```tsx
<ToastProvider>
  <Checkout />
</ToastProvider>;

function Checkout() {
  const toast = useToast();
  return <Button onClick={() => toast.success({ message: "订单已保存" })}>保存</Button>;
}
```

## 受控与非受控

`open` 存在即受控，`onOpenChange` 只报告 timeout/action 关闭意图；省略时使用 `defaultOpen`。Provider record 由命令 API 管理，不混用 declarative open。

## 表单集成

不作为字段或 validation fact。表单提交成功/失败后可由业务调用 toast；action 固定 `type=button`，不会提交祖先 form。

## Props

API 由 `ToastProps`、`ToastShowOptions` 与相关类型生成。message 应简短；duration 非有限值回退 3000，负值夹为 0，超大有限值夹到浏览器 timer 上限；action 有效时长最少 5000。`maxToasts` 默认 20，有限值截断为整数后夹到 1–100。

## Events

`onOpenChange` reason 为 timeout/action。Provider `onClose` 另含 programmatic/clear/overflow：controller close 和 Provider 卸载使用 programmatic；超出容量的新 unique record 不入队并立即报告 overflow；动态缩容以 overflow 淘汰最新 queued record。正常接纳的记录只回调一次。action reject 调用 `onActionError`（若提供）并保持展示；根同时输出 `data-action-error=true`，因此未提供回调时错误仍可观察且不产生未处理 Promise rejection。错误观察器自身抛出的异常也会被隔离。关闭、同 id 替换或 Provider 卸载后才完成的旧 action 不再关闭新状态，也不再报告旧错误。

## Ref 与命令式方法

声明式 ref 指向 toast root。同 id `show` 是完整替换，省略 action/onActionError/onClose 等可选字段会清除旧值；controller `update` 是局部更新，可显式传 `undefined` 清除任一可选字段。两者均不改变队列位置；active 变更会重新开始完整 duration，queued 变更会在到达队首后获得完整 duration。`close` 关闭自己的 active/queued record；stale 或 overflow controller 不会影响同 id 后续新记录。Provider 卸载后保留的 API/controller 为空操作。

## 键盘操作

| 按键          | 行为                                               |
| ------------- | -------------------------------------------------- |
| Tab           | 仅当有 action 时按页面自然顺序进入按钮，并暂停计时 |
| Enter / Space | 执行 action；pending 时按钮 disabled               |

Toast 不捕获 Escape、不创建 focus trap，也不恢复/移动焦点。

## 触摸与手势

无 swipe dismiss；action 是至少 44px 原生按钮。viewport `pointer-events:none`，只有 toast/action 区域响应 pointer，不遮挡页面。

## 无障碍

普通/成功使用 polite status，警告/危险使用 assertive alert，且始终显式 `aria-atomic=true`。action 不嵌入 live region 以免重复播报；action pending 使用 `aria-busy`。

声明式单个 Toast 在内容出现时直接公告。Provider 管理的 Toast 使用独立、视觉隐藏的 live announcer：首条队首立即公告；同 id 或当前队首的 message/tone 连续变化时，视觉内容立即变化，announcer 先清空，并在距上次公告满 500ms 时仅发布最新值；从 polite `status` 升级为 assertive `alert` 会绕过等待。message 与 tone 均未变化的展示/计时配置更新不会重播；待公告记录若先关闭则取消。该策略把进度流限制为最多每秒两次播报，又不延迟真正紧急的错误。

依据 [WAI-ARIA `status`](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA22.html) 与 [WCAG 4.1.3 说明](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)：状态消息应在不移动焦点的情况下可被辅助技术识别，完整消息应为 atomic；非紧急内容不应使用 assertive，且需避免应用过度“健谈”。真实 VoiceOver/TalkBack/NVDA 的打断、队列与重复文本行为仍属于发布前人工矩阵，不能由 DOM 测试代替。

## 动效

open/closed 使用 opacity+小幅 transform Token。ConfigProvider `motion=reduced` 将 Portal 时长归零，系统 reduced-motion 取消 transition；provider reduced 模式不等待 exit 队列间隔。文档页进入后台时暂停 countdown，恢复可见后继续剩余时长；hover、focus、visibility 与 action pause 可叠加，必须全部解除才继续。动态移除聚焦 action 或迁移 Portal 时会清理已失效的 focus/pointer pause，避免倒计时永久冻结。

## 主题与定制

tone、position、icon、action、container、class/style 是稳定入口。Portal boundary 携带 theme/motion class 与 data 属性；forced-colors 使用 Canvas/ButtonText 并移除 shadow。

## SSR 与 Next.js

组件为 client component。closed Toast、空 Provider 和 open Toast 均可安全 SSR；open Portal 服务端及 hydration 首帧原位输出，hydration 后再迁移到配置的容器，并保留 locale、dir、theme 与 motion boundary。首屏是否公告仍由业务状态决定；不要在 server 与 hydration effect 各发一次相同反馈。

## RTL 与国际化

Portal 显式复制 `dir/lang`；icon/action 间距为 logical margin，safe-area 同时处理左右 inset。组件无内置消息文案，业务负责 locale。

## 浏览器与 WebView

依赖 Portal、Promise、requestAnimationFrame、CSS variables 与 safe-area env。Chrome/WebView 70 和 iOS 13 静态语法可用；宿主需提供全局 Token CSS。

## 边界情况与已知限制

- FIFO 一次只显示一条；Provider 默认容纳 20 条、最高 100 条。达到上限时拒绝最新 unique record，但同 id 替换仍可用；运行时降低上限会保留 FIFO 头部，以 overflow 淘汰最新 queued record，并在 160ms 退场期后收敛。高频事件应使用稳定 id 合并。
- 异步 action 不注入 AbortSignal；关闭/卸载会让 run 失效并禁止跨生命周期回写。
- 不支持 swipe dismiss、堆叠、多 action、手动 close icon 或全局模块级 singleton。
- message 为 ReactNode，但长交互内容不应放入 Toast。

## 性能预算

Provider 只渲染一个 toast；visible、queued 与 exiting 记录合计由 `maxToasts` 限制，消息 timeout 仅属于队首，退场项各有一个短 timer。用 id 聚合进度更新；容量不足时应在 `onClose({ reason: "overflow" })` 中记录或降级，而不是重试风暴。
