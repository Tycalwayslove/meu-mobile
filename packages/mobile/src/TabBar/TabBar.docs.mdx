# TabBar

## 当前能力

2–5 个一级目的地导航；非空 `href` 使用原生 link，无 `href` 使用 `type="button"`。支持 `aria-current="page"`、受控/非受控路由、Badge 名称、动态 items、Safe Area、禁用、横屏、RTL、长文案和 active-aware icon。

## 何时使用

用于移动 H5 的稳定一级页面入口。

## 何时不要使用

页面内部内容切换使用 Tabs；瞬时操作不要伪装成目的地；超过五项改用菜单或信息架构调整。

## 结构与状态

`nav → items → a|button → decorative icon + label`，可选 Badge 与底部 SafeArea。`nav` 透传原生属性；调用方可用 `aria-label` 或 `aria-labelledby` 命名，没有提供时按 locale 使用「主导航」/“Primary navigation”。状态为 current、idle、disabled、hover（仅 hover 设备）、pressed、focus。

## 基础用法

```tsx
<TabBar value={route} items={routes} onChange={(key) => navigate(key)} safeArea />
```

## 受控与非受控

`value !== undefined` 时受控，`null` 或无效/禁用 key 表示无当前页，组件不会擅自回写；非受控从有效 `defaultValue` 或首个 enabled item 初始化。当前项被删除或禁用时会永久归一到首个 enabled item；只重排稳定 key 不改变 current。重复 key 只保留第一项，避免多重 current 和 React identity 冲突。路由框架应使用受控模式。

## 表单集成

不适用：button 固定 type=button，导航不会提交祖先 form。

## Props

| 属性           | 契约                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| `items`        | 有序目的地；建议 2–5 项；key 必须唯一稳定，重复时第一项生效                                            |
| `value`        | 受控 current key；`null`、未知或 disabled key 均不标记 current                                         |
| `defaultValue` | 非受控初值；无效时回退首个 enabled item                                                                |
| `onChange`     | 新 enabled 目的地请求成为 current 后触发；同一 key 不重复触发                                          |
| `safeArea`     | 消费 bottom 以及物理 left/right viewport inset；不负责 fixed 或页面占位                                |
| 原生 nav props | 支持 `id`、`className`、`style`、`aria-label`、`aria-labelledby` 等；`children`/原生 `onChange` 不开放 |

`TabBarItem`：

| 字段                   | 契约                                                                                                                  |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `key`                  | 选择值与 React identity；必须稳定唯一                                                                                 |
| `label`                | 可见标签及默认 accessible name；不要嵌套交互元素                                                                      |
| `icon`                 | 装饰图标或 `(active) => ReactNode`；始终从可访问树隐藏                                                                |
| `href`                 | 非空时固定渲染 anchor；空串/省略时渲染 button                                                                         |
| `disabled`             | button 使用原生 `disabled`；link 保持 anchor/role，但从 SSR 起移除 live `href`，使用 `aria-disabled` 与 `tabIndex=-1` |
| `badge` / `badgeLabel` | 短计数/状态与其可访问含义；纯计数可沿用可见文本，业务状态应给 `badgeLabel`                                            |
| `ariaLabel`            | 可见 label 不足以命名目的地时覆盖整项 accessible name                                                                 |
| `onClick`              | enabled 项选择前调用；`preventDefault()` 同时取消选择请求和原生链接导航                                               |

## Events

`item.onClick` 先执行；调用 `event.preventDefault()` 会同时取消选择请求与链接导航。未取消时，`onChange(key,event)` 仅在新 enabled 项请求成为 current 时触发。disabled 项会取消默认行为并停止冒泡，不调用两个回调。受控模式只发布事件，不进行乐观 current 更新。

## Ref 与命令式方法

React 19 `ref` prop 指向稳定的 `nav`；支持 object/callback ref，并透传 callback ref 返回的 cleanup；旧式 callback ref 在卸载时仍收到 null。无命令式路由 API。需要聚焦具体目的地时由路由层管理，不公开内部 item ref。

## 键盘操作

| 按键            | 行为                                |
| --------------- | ----------------------------------- |
| Tab / Shift+Tab | 按 DOM 顺序遍历 enabled link/button |
| Enter           | 激活 link 或 button                 |
| Space           | 激活 button；link 保持原生行为      |

组件不把主导航伪装成 ARIA tablist，因此不劫持方向键。动态删除或禁用已聚焦项时，焦点移到归一后的 current，受控值无效时移到首个 enabled item；若用户焦点不在 TabBar 内则不抢焦点。

## 触摸与手势

支持范围内每项至少 44×44 CSS px 并均分宽度，默认 56px 高；横屏低高度使用 48px 最小高度。使用 `touch-action: manipulation`，无滑动或长按手势。组件不是 fixed，页面布局必须为其保留实际高度。

## 无障碍

nav 必须有名称；当前目的地使用 `aria-current="page"`；icon `aria-hidden`；Badge 可通过 `badgeLabel` 提供状态含义。禁用 button 使用原生 `disabled`；禁用 link 保持 anchor 与显式 link role，从服务端 HTML 起移除 live `href`，以 `aria-disabled` 暴露状态并退出顺序焦点，因此 hydration 前后都没有可触发的导航 URL。键盘焦点使用基础 `:focus` 轮廓，不依赖 `:focus-visible`；因此支持档可靠可见，静态语法基线中的 Chrome 70/iOS 13 也能识别，代价是浏览器在点击后保留焦点时仍可能显示焦点环。这是可见性优先的明确取舍。选中与禁用均不只靠颜色：forced-colors 使用 Highlight/HighlightText/GrayText，普通主题下 disabled 同时使用持久 surface 与透明度。disabled 不是授权边界，业务权限必须由路由和服务端继续校验。

## 动效

背景与颜色过渡使用 motion token；`prefers-reduced-motion: reduce` 缩短到 1ms。无循环动效和 layout 动画。

## 主题与定制

使用 surface/border/subtle/muted/ink/accent token；不硬编码品牌色。forced-colors 分别使用 LinkText、ButtonText、Highlight/HighlightText 和 GrayText。

## SSR 与 Next.js

服务端输出确定性 nav、current、disabled link/button、Badge 与 SafeArea；render 不读取 `window`/`document`。真实 `hydrateRoot` 覆盖零 recoverable error 以及 hydration 后 button 路由更新。核心不依赖 `next/navigation`；需要 Next 路由时可让 link 保留 `href`，在 `item.onClick` 中 `preventDefault()` 后交给 router。服务端与客户端首屏 `value`、items、locale 和 label 必须一致。

## RTL 与国际化

flex 与逻辑 Badge 偏移继承最近的 `dir`；Safe Area 使用物理 left/right inset，避免横屏刘海。路由 key 不本地化，label/ariaLabel/badgeLabel 由业务翻译。默认 nav 名称支持中文/英文。长标签保留完整可访问文本，视觉在单行边界内省略；NarrowLongLabels Story 固定覆盖 320px/四项/长中英文类文案。

## 浏览器与 WebView

完整支持矩阵为 Android Chrome/WebView 89+、iOS Safari/WKWebView 15+。Chrome/WebView 70+ 与 iOS 13+ 仅用于构建产物旧语法静态扫描，不代表完整运行时承诺；Chromium/WebView 79–88 与 iOS 13–14 属观察档。焦点只使用基础 `:focus`；`safeArea` 需要应用 viewport 配置允许系统 inset，不支持 `env()` 时回退 0。组件没有 ResizeObserver、媒体查询 JS 或 UA 分支。

## 边界情况与已知限制

动态删除/禁用当前非受控项会清理旧 identity，重新加入时不会意外跳回；重复 key 第一项胜出。空 `href` 按无目的地 button 处理。`ariaLabel` 会覆盖 label 与 Badge 的组合 accessible name。组件不 fixed、不拥有浏览历史、pending、prefetch、target/rel 或路由错误状态；这些由路由适配层负责。异步导航失败时受控 `value` 应保持原路由。少于 2 或多于 5 项仍会渲染，但信息架构与触控宽度不在推荐契约内。

## 性能预算

每次 render 对最多五项做 O(n) 去重、current 查找和焦点可用性判断；无监听、测量、ID 生成或第三方运行时。Badge/SafeArea 是共享已有原语。稳定 key 使重排复用既有 link/button DOM；变更 `href` 有无会按契约更换元素类型。
