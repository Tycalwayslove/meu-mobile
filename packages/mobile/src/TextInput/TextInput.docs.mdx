# TextInput

## 当前能力

- 原生单行 input，支持 ref 和除原生 `size` 外的 input 属性。
- small/medium/large、default/error、disabled 与 clearable。
- 与 Field context 自动关联 id、description 和 error；支持显式 ARIA 覆盖。
- 保留显式 `aria-invalid="false"`、`grammar` 和 `spelling` token；后两者同时进入 error 视觉态。
- clear 在受控与非受控模式下均先派发原生 input/change 契约，再调用 `onClear`；支持 readOnly 和中英文清除名称。

## 何时使用

用于姓名、手机号、搜索词、短文本、密码等单行输入。应根据数据类型设置 `type`、`inputMode`、`autoComplete` 和 `enterKeyHint`。

## 何时不要使用

多行内容使用 TextArea；数字加减使用 Stepper；固定选项使用 Selector/Radio；特殊数字键盘仅在系统键盘不能满足时使用。

## 结构与状态

结构为 input 与可选清除按钮。当前状态包括 default、focus、error、disabled 与 readOnly；V2 需补齐 autofill、IME composing、password reveal 组合和异步校验状态契约。

## 基础用法

```tsx
<Field label="手机号" error={error}>
  <TextInput inputMode="tel" autoComplete="tel" value={value} onChange={onChange} />
</Field>
```

## 受控与非受控

遵循原生 `value/onChange` 与 `defaultValue`。不要在生命周期中切换受控模式。clear 使用原生 value setter 派发冒泡 input，受控调用方可在 `onChange` 中提交空值；该路径已有 React 测试。

## 表单集成

透传 `name`、`required`、`disabled`、`readOnly`、`onBlur` 和 ref，可参与原生 FormData。React Hook Form 使用 `MeuFormTextInput`；V2 需覆盖 dirty、touched、服务端错误、首次错误聚焦和 reset。

## Props

专有 Props 为 `clearable`、`onClear`、`size`、`status`，其余来自原生 input。API 表由 API Extractor 生成。

## Events

- `onChange`：原生 React change 语义，由输入产生。
- `onClear`：input change 派发后调用；当前无 details，也不区分 pointer/keyboard 来源。
- 原生 `onInput/onBlur/onFocus/onComposition*` 均透传。

clear 顺序固定为值置空 → 冒泡 input/change → 恢复 input 焦点 → `onClear`。

## Ref 与命令式方法

ref 指向真实 `HTMLInputElement`，可使用 focus、select、setSelectionRange 等原生能力。

## 键盘操作

| 按键            | 行为                                            |
| --------------- | ----------------------------------------------- |
| Tab / Shift+Tab | 在 input、清除按钮和相邻控件间移动              |
| 输入法组合键    | 由原生 input 处理，组合期间不得错误提交或格式化 |
| Enter           | 由表单和 `enterKeyHint` 场景决定                |

## 触摸与手势

无自有手势。清除按钮必须达到 44×44 CSS px，且不能遮挡文本、选择手柄或浏览器密码管理 UI。

## 无障碍

input 必须有 label；推荐由 Field 生成。error 通过 `aria-invalid` 和 `aria-describedby` 关联。调用方的 `grammar`/`spelling` 语义不会折叠为 `true`，显式 `false` 在无 Field/status 错误时原样保留；Field/status 错误优先输出 `true`。清除按钮从 ConfigProvider locale 获取中英文 accessible name。

## 动效

仅使用状态过渡，无业务动效。reduced-motion 下不应影响输入反馈。

## 主题与定制

稳定入口为 size、status、原生属性、Field 组合和全局 Token。内部 wrapper/class 不作为 API。

## SSR 与 Next.js

初始 value/defaultValue 必须在服务端和客户端一致。autoFocus 可能影响 hydration 后体验，不应用作默认生产行为。

## RTL 与国际化

文本方向遵循 DOM；图标、内边距与清除按钮定位使用逻辑方向。清除 label 跟随 ConfigProvider locale。

## 浏览器与 WebView

IME、autofill、密码管理、selection 和虚拟键盘行为必须在 iOS Safari/WKWebView 与 Android Chrome/WebView 真机验证。

## 边界情况与已知限制

- 当前 `onClear` 没有 source/reason details；是否扩展需经过 V2 API 评审。
- 未内建格式化、mask、debounce 或请求逻辑。

## 性能预算

单次输入不应引入额外 layout measurement 或全局监听；格式化和远程校验由调用层节流。

## 测试证据

- Unit: `TextInput.test.tsx`，覆盖 Field 对 caller token 的优先级、受控/非受控 clear、locale、readOnly，以及 `aria-invalid` false/grammar/spelling token
- Story interaction: `Clearable` 验证清除后的值、回调状态与焦点恢复；仓库门禁 `check-storybook-links` 本地验证 `play-fn 80/80`（80 个 Storybook title 均至少一个有意义 play）。
- Storybook 浏览器矩阵：本地扫描器在 390×844 视口验证 374 个 Story × 7 场景（Light、Dark、en-US、RTL、reduced-motion、200% 字体、forced-colors），共 2,618 个组合；有 play 的 Story 必须先返回 `storyFinished=success`，再运行 axe WCAG A/AA，结果为 0 违规、0 `pageerror`。
- 官网 Next 运行时：本地 production build 在 390×844 下逐页验证 68 个组件页的 Light/Dark（136 场景）；主题恢复、H1/预览/API 结构、React `pageerror` / `console.error`（含 hydration mismatch）和 axe WCAG A/AA 均通过。
- Bundle：Rollup tree-shaken ESM（React 与包 peer dependencies external）单一公开值 gzip 3653 B / 32768 B 预算，组合 Brotli 3227 B；共享样式由应用单独导入一次。
- SSR/hydration: `TextInput.ssr.test.tsx` 覆盖原生 input 的 token 输出；隔离 Next 16 App Router 首屏渲染 Field-aware input，hydration 后 clear、错误修正与提交成功且 0 hydration/runtime error
- RTL: 待补
- Reduced motion: 不适用，待静态验证
- Mobile Chromium/WebKit E2E: 两种引擎断言 Zod invalid、Field 归属、受控 fill、clear 后值与焦点恢复、修正后提交；IME/autofill/password 仍待专项与真机
- Chromatic Light/Dark: 有视觉快照，待矩阵化
- Real device: 待补
