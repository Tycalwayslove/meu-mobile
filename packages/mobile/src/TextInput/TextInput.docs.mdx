# TextInput

## 当前能力

- 使用真实单行 input，支持 ref、受控/非受控值，以及除原生 `size` 外的 input 属性。
- 支持 small/medium/large、default/error、disabled、readOnly、loading 与 clearable。
- 自动继承 Field 的 id、description、error；保留 caller 的 `false/grammar/spelling` ARIA invalid token，Field/status error 优先输出 `true`。
- clear 只在可编辑非空值时出现；通过真实 input event 请求空值，恢复 input 焦点后再调用 `onClear`。受控调用方可接受或拒绝空值。
- 非受控值遵循祖先或外部 `form=` 的原生 reset；受控 reset 恢复最新 `value`，取消 reset 不改变当前值。
- loading 公布 caller-owned 异步工作并隐藏 clear，但不锁住编辑、FormData 或原生 form submit；focused clear 被替换时焦点回到 input。

状态保持 `verification`。Unit、SSR、直接 hydration 和 Story interaction 已覆盖核心契约；真机 IME、系统 autofill/password manager、软键盘和读屏仍未完成。

## 何时使用

用于姓名、手机号、邮箱、短文本和密码等原生单行输入。根据数据设置 `type`、`inputMode`、`autoComplete`、`enterKeyHint` 与 `name`。

## 何时不要使用

多行内容使用 TextArea，搜索提交使用 SearchField，数字步进使用 Stepper，固定选项使用 Selector/Radio。格式化、mask、建议列表和 password reveal 应使用明确的业务组合，而不是改变 TextInput 的 native value 契约。

## 结构与状态

DOM 为 wrapper → native input + 可选 clear button/loading status。

- `className/style` 与其余 native 属性作用于 input，保持历史契约。
- wrapper 仅承担定位与 `dir` 同步，不是稳定 DOM API。
- `data-state` 位于 input，优先级为 disabled → loading → readonly → error → default。
- error 视觉可与 loading 同时存在；loading 不是 validation 结果。

## 基础用法

```tsx
<Field label="手机号" error={error}>
  <TextInput
    autoComplete="tel"
    clearable
    inputMode="tel"
    name="phone"
    value={phone}
    onChange={(event) => setPhone(event.currentTarget.value)}
  />
</Field>
```

## 受控与非受控

组件遵循原生 `value/onChange` 与 `defaultValue`，不复制文本值。不要在生命周期内切换受控模式。

- 非受控：浏览器拥有值；组件只跟踪“是否为空”以决定 clear 可见性。原生 input/autofill-like event 和 form reset 会同步该布尔状态。
- 受控：`value` 是唯一事实源。clear 请求空值；调用方不更新时旧值和 clear 都保留。
- reset 不发布 `onInput/onChange/onClear`。非受控恢复当前 `defaultValue`，受控恢复最新 `value`。

## 表单集成

透传 `name/form/required/disabled/readOnly/onBlur` 和 ref。

- disabled input 从 FormData 省略；readOnly input 保留值。
- 祖先 form 与 `form="id"` 外部所有者均支持 reset；外部 form 可晚于 input 挂载，也可由同 ID 新节点替换。
- 被 `onReset.preventDefault()` 取消时保持当前值。
- loading 不改变 FormData，也不阻止 Enter submit；是否禁止提交由 form/button 所有者决定。
- React Hook Form 使用 `MeuFormTextInput`；dirty/touched/server error 属于 form-react adapter 契约。

## Props

- `clearable`：非空、可编辑且非 loading 时显示 44×44 clear；默认 false。
- `clearLabel`：clear accessible name；默认跟随 ConfigProvider 中英文 locale。
- `loading/loadingLabel`：显示 polite status、设置 input `aria-busy` 并隐藏 clear；不禁用输入。
- `onClear`：值请求、input/change 通知及 focus 恢复之后调用。
- `size`：small/medium/large 控制高度和 padding。
- `status`：default/error 视觉状态；error 会设置 `aria-invalid=true`。
- `dir`：同时设置 wrapper 与 input，保证组件级 RTL 的文本和尾部操作一致。

其余 Props 来自 native input；API 表由 `TextInputProps` 生成。

## Events

- `onInput`：真实输入、autofill-like input 和 clear 派发的冒泡 input event。
- `onChange`：React 对 native input 的 change 契约；clear 通过同一 input event 进入该回调。
- `onClear`：上述事件处理和 input focus 恢复后调用；当前无 details，不区分 pointer/keyboard 来源。
- `onBlur/onFocus/onComposition*/onKeyDown`：原样透传；组件不拦截 IME 或 Enter。

clear 顺序固定为 DOM value 置空 → 冒泡 input → React `onInput/onChange` → focus input → `onClear`。它不会额外派发浏览器原生 `change` event。

## Ref 与命令式方法

ref 指向真实 `HTMLInputElement`，可使用 `focus/select/setSelectionRange` 并读取 selection/form。clear 后空值 selection 位于 0；loading 替换已聚焦 clear 时把焦点还给 input。password、number 等类型对 selection API 的原生限制保持不变。

## 键盘操作

| 操作            | 行为                                                   |
| --------------- | ------------------------------------------------------ |
| Tab / Shift+Tab | 在 input、非空时的 clear 和相邻控件间移动              |
| 输入法组合键    | 完全由 native input 处理；组件不格式化或提交           |
| Enter           | 完全由 input/form 和 `enterKeyHint` 场景决定           |
| clear click     | 请求空值，保持 input focus，并让虚拟键盘继续由输入拥有 |

IME 完全由 native input 处理；组件不拦截 composition 事件，也不在 Enter 时自行提交或格式化。

## 触摸与手势

无自有手势。clear 为 44×44 CSS px；mouse down 不抢走 input 焦点。clear click 请求空值后保持 input focus，使虚拟键盘继续由输入拥有。尾部 padding 为 clear/loading 保留空间，第三方密码管理器注入的按钮仍需宿主真机检查。

## Autofill 与 password

`type/autoComplete/name` 直接落在 native input，组件不读取密码、不提供 reveal，也不关闭浏览器密码管理器。浏览器派发 input 时 clear 可见性会同步；不派发 input 的第三方直接 DOM 注入可能延迟到下一次用户输入或 rerender。

不要从服务端以 `value/defaultValue` 预填真实密码：这会把秘密写入 HTML/DOM，与组件是否遮蔽显示无关。密码输入应初始为空，并交由浏览器或受信任密码管理器填充。

## 无障碍

input 必须有 label，推荐由 Field 生成。error 通过 `aria-invalid` 与 `aria-describedby` 关联；通过嵌套布局消费 Field context 时，显式 `aria-describedby`（包括空字符串 opt-out）优先于 context，直接子控件仍遵循 Field 的 ID 合并契约。grammar/spelling token 不会无故折叠。clear 是有名称的 native button，可用 `clearLabel` 为密码等场景具体化。loading 使用 atomic polite status，并在 input 设置 `aria-busy`；它不是 disabled/readOnly 的替代。

## 动效

唯一持续动效是 loading spinner；`ConfigProvider motion="reduced"` 或 `prefers-reduced-motion: reduce` 均会停止旋转，status 与 `aria-busy` 继续表达状态。loading 只覆盖 `data-state`，不会移除 `status="error"` 的 error border 或 `aria-invalid=true`；单元和 ReducedMotionLoading Story 直接覆盖该组合。

## 主题与定制

input border、clear 和 spinner 在 forced-colors 下使用系统颜色。颜色、尺寸、圆角来自 Meu tokens；稳定定制入口是原生 input 的 `className/style`、公开 Props 与全局 tokens，wrapper 与内部 class 不是公开 API。

## SSR 与 Next.js

SSR 输出真实 input、value/type/autoComplete/disabled/error 与 loading status，不读取 window/document。`TextInput.hydration.test.tsx` 以相同 props 调用 `hydrateRoot`，覆盖无 mismatch 以及 hydration 后 clear/change/focus。首次服务端与客户端 `value/defaultValue/loading` 不一致仍是调用方 mismatch；`autoFocus` 不应用作默认生产策略。

## RTL 与国际化

组件级 `dir` 同时设置 wrapper/input，使 clear/loading 尾部位置与文本方向一致。padding 使用 logical properties；RTL 有单元与 Story 入口。clear/loading label 跟随 ConfigProvider locale，也可显式覆盖。mixed bidi、阿拉伯语 IME 和系统字体放大仍需真机。

## 浏览器与 WebView

运行时代码使用 native input/button、value descriptor、基础 Event、setTimeout 和 React state/effect，没有引入超出 Chrome/WebView 70 或 iOS 13 的强制 JS API。logical padding 在目标基线可用；旧宿主可安全忽略不识别的 forced-colors/reduced-motion media query。静态兼容与 jsdom 不代表真机通过。

## 边界情况与已知限制

- `onClear` 尚无 source/reason details；扩展需经过 API 评审。
- loading 是调用方状态，不创建、去重或取消请求，也不阻止 form submit。
- 组件不内建格式化、mask、debounce、请求或 password reveal。
- 极少数不派发 input 的密码管理器注入可能使 clear 可见性暂时滞后。
- 受控/非受控切换不受支持，遵循 React native input 约束。

## 性能预算

每个实例仅维护 clear 可见性布尔值和少量 refs，不测量布局。组件在 input 的 `ownerDocument` 注册一个 reset 委托 listener，并在每次事件时核对 `event.target === input.form`，因此不会响应无关 form，且卸载时会清理；这是支持外部 owner 晚挂载/替换所需的常数级监听。loading spinner 仅使用 CSS。格式化和远程校验由调用层节流、取消。

## 测试证据

- Unit：Field/ARIA token、受控接受/拒绝 clear、非受控 input/autofill-like 更新、password clear、IME 事件透传、selection/focus、祖先/外部/晚挂载/替换/cancel/controlled reset、disabled/readOnly FormData、loading 编辑和 form submit、loading+error、provider reduced motion、RTL、locale。
- SSR：native token、password/autoComplete、loading 与 disabled。
- Hydration：真实 `hydrateRoot` 无 mismatch，hydration 后 clear/change/focus。
- Story interaction：Clearable 覆盖值/回调/focus；NativeFormReset 覆盖 default/FormData；LoadingFocusTransfer 覆盖 loading 焦点移交；ReducedMotionLoading 覆盖 provider motion 与 loading/error 语义。Password/autofill 与 RTL Story 提供人工入口。
- 官网 Next 运行时：既有本地 production 双引擎证据覆盖 Field invalid、受控 fill、clear/focus、修正与提交；本轮未重新执行或扩大共享 E2E，loading、外部 form/reset 与受控拒绝仍待后续定向浏览器验证。
- Bundle：Rollup tree-shaken ESM（React 与包 peer dependencies external）单一公开值 gzip 4512 B / 32768 B 预算，组合 Brotli 3976 B；共享样式由应用单独导入一次。
