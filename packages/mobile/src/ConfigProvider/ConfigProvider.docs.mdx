# ConfigProvider

## 当前能力

- 通过 React Context 向子树提供 `locale`、`dir`、`theme`、`motion` 与默认 Portal 容器。
- 根级默认值为 `zh-CN`、`ltr`、`system` theme、`system` motion 和 `document.body` Portal 策略。
- 嵌套 Provider 对未传入字段执行逐字段继承；显式 `portalContainer={null}` 不会被当作缺省值。
- DOM 边界同步输出 `lang`、`dir`、`data-meu-theme` 与 `data-meu-motion`，便于语义继承和 CSS Token 生效。
- 统一 Overlay Portal boundary 除复制上述属性与 motion Token 外，也复制主题边界 class，因此移出 Provider DOM 后的原生控件仍保留 `color-scheme`。
- `system` theme 和 motion 都通过 CSS media query 解析；渲染期间不读取 `window`、`document`、`matchMedia` 或本地存储。
- `portalContainer` 函数仅作为惰性配置保存，ConfigProvider 渲染和 SSR 阶段不会调用它。
- light/dark/system 边界同步声明 `color-scheme`，原生表单控件可与 Meu 主题匹配；旧 WebView 不支持时安全忽略。
- React 19 `ref` 直接指向真实 `div` 边界，并保留 callback ref 的卸载清理语义。

当前为 V2 `verification` 状态；跨 Portal 方向与动效传播、全库移动端 E2E 和扩展场景矩阵已完成，真机与最终视觉审批仍待统一验收，不能标记为 commercial。

## 何时使用

- 在 Next.js H5 应用的客户端组件边界内建立 Meu Mobile 全局配置。
- 在多语言、RTL 预览、暗色区域、弹层挂载区域或需要主动减少动效的局部子树建立嵌套作用域。
- 测试或 Story 中显式固定 locale/theme/motion，减少环境差异造成的快照漂移。

## 何时不要使用

- 不用它保存登录态、业务数据、表单值或请求状态。
- 不要为每个叶子组件重复包裹 Provider；优先在稳定布局边界建立作用域。
- 不要把 `portalContainer={null}` 当作关闭 Portal。它表示由具体 Portal 在当前位置渲染，层叠与裁切责任由调用方承担。

## 结构与状态

结构为一个 Context Provider 和一个真实 `div` 配置边界。它没有 pressed、selected、invalid 或 loading 状态。配置状态由属性完全驱动：

- `data-meu-theme="light|dark|system"`
- `data-meu-motion="system|reduced"`
- `lang="zh-CN|en-US"`
- `dir="ltr|rtl"`

`className` 会追加到内部主题/动效策略 class，`style` 应用于同一边界。

## 基础用法

```tsx
<ConfigProvider locale="zh-CN" dir="ltr" theme="system" motion="system">
  <App />
</ConfigProvider>
```

局部覆盖只需传变化字段：

```tsx
<ConfigProvider locale="en-US" dir="rtl" theme="dark">
  <Checkout />
  <ConfigProvider locale="zh-CN">
    <AddressHelp />
  </ConfigProvider>
</ConfigProvider>
```

内层 `AddressHelp` 解析为 `zh-CN + rtl + dark`，其余配置继续继承。

## 受控与非受控

ConfigProvider 没有非受控状态。所有配置均由 Props 驱动；Props 更新后 Context 与 DOM 属性在同一次 React 提交中更新。省略字段表示继承最近父级；只在没有父级时使用根默认值。

## 表单集成

不适用。ConfigProvider 不注册字段、不参与校验，也不修改 `FormData`。表单适配器可读取其 locale 来生成内建提示，但业务校验文案仍由表单层负责。

## Props

Props 表由 TypeScript/TSDoc 与 API Extractor 生成。跨字段规则如下：

- `locale`: `zh-CN | en-US`；根默认 `zh-CN`，嵌套省略时继承。
- `dir`: `ltr | rtl`；根默认 `ltr`，不提供 `auto`，避免 UI 控件方向由不可信文本内容推断。
- `theme`: `light | dark | system`；根默认 `system`。
- `motion`: `system | reduced`；根默认 `system`。不提供强制 full motion，以免覆盖用户的减少动态效果偏好。
- `portalContainer`: `HTMLElement | (() => HTMLElement) | null`。省略时继承；根省略时具体 Portal 默认使用 `document.body`；`null` 表示原地渲染。
- `className`、`style`: 作用于真实配置边界。调用方通过 `style` 覆盖动效 Token 时，同时承担无障碍责任。
- `ref`: React 19 DOM ref，目标为真实配置边界 `HTMLDivElement`。

## Events

不适用。组件不发出自定义事件，也不监听系统主题、语言、方向或本地存储变化。主题/语言切换事件属于应用状态层。

## Ref 与命令式方法

`ref` 指向真实 `HTMLDivElement`，支持对象 ref、callback ref 与 React 19 callback cleanup；不公开额外命令式方法。不要通过 ref 改写 `lang`、`dir` 或 `data-meu-*`，这些值仍由 Props 驱动。

## 键盘操作

| 按键   | 行为                                                |
| ------ | --------------------------------------------------- |
| 不适用 | Provider 本身不可聚焦，不修改子组件的原生键盘行为。 |

## 触摸与手势

不适用。Provider 不注册 pointer、touch 或 gesture 监听器，不阻止滚动，也不创建触控目标。

## 无障碍

- `lang` 与 `dir` 位于真实 DOM 祖先上，子树可获得语言和书写方向语义。
- Provider 不增加 ARIA role，避免制造无意义的可访问性层级。
- `motion="reduced"` 把进入/退出动效 Token 设为 `0ms`；`system` 通过 `prefers-reduced-motion` 自动降级。
- `color-scheme` 只协调浏览器原生控件、滚动条与系统 UI 的配色，不替代组件自身的 forced-colors 和对比度处理。
- `dir` 不会自动镜像有语义方向的图标；方向图标仍需由对应组件规则处理。
- 渲染到 `document.body` 的 Portal 内容不是 Provider DOM 后代。核心 Overlay 通过统一 boundary helper 复制 `lang`、`dir`、theme、motion 与 motion class；新增 Portal 消费者必须复用该契约。

## 动效

Provider 自身没有视觉动画。它控制两个稳定时长 Token：`--meu-motion-enter` 与 `--meu-motion-exit`。

- `system`: 常规值分别为 180ms 和 140ms；用户设置 reduced motion 时均为 0ms。
- `reduced`: 无条件把两个时长设为 0ms。
- 缓动 Token不被修改；零时长时不会产生可见位移过程。

组件自己的非 Token 动画仍必须实现独立 reduced-motion 降级；Provider 不能替代组件级审计。

## 主题与定制

稳定定制面为配置 Props、语义 Token 和四个公开 DOM 属性。内部 vanilla-extract class 名不是公开 API。`style` 可设置局部 CSS 变量，但主题色应优先通过 Token 构建流程维护，避免产生不可审计的局部色值。

## SSR 与 Next.js

- 文件为 Client Component，但可由 Next.js 预渲染；服务端输出确定性的 DOM 属性和 class。
- `system` 不在 JavaScript 中计算实际 light/dark，因此服务端与 hydration 标记一致，实际色值由 CSS media query 选择。
- `data-meu-theme="system"` 与 `color-scheme: light dark` 会随系统偏好由 CSS 引擎重算，无需事件订阅；保存的用户选择仍应由服务端首屏 Prop 决定。
- Portal 容器函数在 Provider 中不会执行，允许传入闭包；具体 Portal 只会在客户端挂载后解析。
- 不要在 Server Component 中创建或传递 `HTMLElement`。Next.js 中应在客户端边界通过 ref 获得容器，或传递客户端惰性函数。

## RTL 与国际化

- `locale` 只控制 Meu Mobile 内建字符串与 `lang`；不会格式化业务金额、日期或地址。
- `dir="rtl"` 写入 DOM 并进入 Context。使用 CSS 逻辑属性的子组件会自然镜像；尚未完成 RTL 审计的组件需逐项验证。
- 仅支持 `zh-CN` 与 `en-US` 内建字符串。扩展 locale 是公开类型变化，需要先补齐全组件词条与降级策略。

## 浏览器与 WebView

实现只依赖 React Context、标准 `lang/dir/data-*`、CSS 自定义属性和 media query，不注册仅现代浏览器提供的事件 API。V2 正式支持矩阵为 iOS Safari/WKWebView 15+ 与 Android Chrome/WebView 89+；iOS 13–14 和 Chromium 79–88 仅观察、不承诺。构建仍执行 Chrome 70 静态语法门禁，用来阻止可避免的新语法进入客户端产物，但该门禁不等于运行时支持声明。旧 WebView 必须加载 `@meu/mobile/styles.css`，否则 theme/motion Token 不生效；`prefers-reduced-motion` 不支持时保留常规时长，调用方仍可显式设为 `reduced`。

## 边界情况与已知限制

- Mask/Dialog/Popup/BottomSheet/Popover 已覆盖 body Portal；ImageViewer、Picker、Toast 等其余 Portal 消费者仍需在对应批次核对并迁移统一 boundary。
- `system` theme 不包含用户选择持久化；若产品允许手动选择，应用需保存值并在服务端提供相同初始值。
- Context value 在配置值变化时更新；高频创建新 portal resolver 函数会使消费者重渲染，应保持函数引用稳定。
- `className` 与 `style` 作用于新增的真实 `div`，Provider 不是无 DOM 包装器。
- 不支持 `dir="auto"`、任意 locale 字符串、跨 iframe/跨 Document Portal 继承。

## 性能预算

每个 Provider 创建一个 Context value 和一个 `div`，没有 effect、订阅或事件监听。Context value 通过 `useMemo` 按解析后的五项配置稳定。应用根部配置不应高频变化；大子树切换 locale/theme 会按 React Context 语义重新渲染消费者。

- Unit: `ConfigProvider.test.tsx` 覆盖默认值、DOM 属性、className、逐字段嵌套继承、显式覆盖、Portal null/惰性函数、ThemeProvider 身份，以及 React 19 callback ref 清理。
- Story interaction: `NestedConfiguration` 验证逐字段覆盖与继承边界；`check-storybook-links` 已验证全库 81/81 title 各至少一项关键 play，本 title 的 play 在本地扫描中返回 `storyFinished=success`。
- 本次定向 Storybook 扫描：ConfigProvider 4 个 Story × Light/Dark，共 8 个场景，play 与 axe WCAG A/AA 均通过。
- Storybook 浏览器矩阵：本地扫描器在 390×844 视口验证 444 个 Story × 7 场景（Light、Dark、en-US、RTL、reduced-motion、200% 字体、forced-colors），共 3,108 个组合；有 play 的 Story 必须先返回 `storyFinished=success`，再运行 axe WCAG A/AA，结果为 0 违规、0 `pageerror`。
- 官网 Next 运行时：本地 production build 在 390×844 下逐页验证 68 个组件页的 Light/Dark（136 场景）；主题恢复、H1/预览/API 结构、React `pageerror` / `console.error`（含 hydration mismatch）和 axe WCAG A/AA 均通过。
- Bundle：Rollup tree-shaken ESM（React 与包 peer dependencies external）2 个公开值组合 gzip 769 B / 32768 B 预算；最大单值 `ConfigProvider` 为 720 B / 32768 B 预算，组合 Brotli 668 B；共享样式由应用单独导入一次。
- SSR/hydration: `ConfigProvider.ssr.test.tsx` 与 `ConfigProvider.test.tsx` 覆盖无浏览器全局 SSR、惰性 Portal 和 system hydration 无 recoverable error。
- RTL: 单元测试和 `NestedConfiguration` Story 覆盖 Context/DOM 方向；全组件视觉镜像待逐批验证。
- Reduced motion: 单元测试覆盖嵌套策略，CSS media/reduced class 已实现；真实浏览器 computed style 待 E2E。
- Mobile Chromium/WebKit E2E: Next production consumer 已在双引擎直接验证 Provider 初始 `theme="light"` 边界、受控切换为 `dark`、两种固定主题下全页 axe WCAG A/AA 0 违规；独立 `theme="system"` / `motion="system"` 边界会随模拟系统 Light/Dark 切换 ink/canvas Token，并在 `prefers-reduced-motion: reduce` 下把 enter duration 从 180ms 解析为 0ms。隔离的 `overlay-lifecycle.spec.ts` 进一步覆盖嵌套 ConfigProvider/ThemeProvider 下 Popup Portal 的 locale、dir、theme、motion、颜色与时长 Token 及 `color-scheme`；所有路径 hydration 后保持 0 `pageerror` / `console.error`。
- Chromatic Light/Dark: Story 可生成快照；基线接受状态由 Chromatic 构建记录决定。
- Real device: 待补 Android WebView 与 iOS Safari。

### 待优化

- 完成其余 Overlay 在 body Portal 根节点复用统一 locale、dir、theme 与 motion boundary。

### 已完成

- 修复嵌套 Provider 省略字段时被重置为根默认值的问题。
- 新增 `dir` 与 `motion` 配置契约，并输出稳定 DOM 标记。
- `useMeuConfig()` 返回的 `MeuConfig` 将 `dir` 与 `motion` 明确为始终存在的解析值；Provider Props 仍保持可选继承语义。
- 保留 `portalContainer={null}` 与惰性 resolver 语义，SSR 期间不访问 DOM。
- 使用纯 CSS 解析 system theme/motion，验证服务端输出与 hydration 一致。
- 为显式及 system 主题声明 `color-scheme`，让原生控件跟随固定主题或系统偏好。
- 为真实 Provider DOM 边界增加 React 19 `ref` 与 callback cleanup 证据。
- 为公开类型、Props、函数和 ThemeProvider alias 补充 TSDoc/release tag；新增 Context 字段在公开类型中保持 optional，以兼容已有 `MeuConfig` 对象字面量，运行时始终解析为具体值。
- Next H5 production consumer 已在 Chromium/WebKit 验证固定 light/dark 受控切换、system 主题/动效媒体查询、实际 Token 计算值、全页无障碍与无运行时错误；该证据不替代真机验收。
- 新增隔离 Next H5 嵌套 Provider → Popup Portal 生命周期矩阵，并让统一 Portal boundary 保留主题 `color-scheme` class。
