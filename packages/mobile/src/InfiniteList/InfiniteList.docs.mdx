# InfiniteList

## 当前能力

- 最近 overflow 滚动祖先的 IntersectionObserver 预加载（即使首屏尚未溢出）、始终可用的手动入口、失败重试和完成状态。
- 同步并发锁保证 observer/按钮不会重复请求；`hasMore=false` 或卸载会中止本次 signal、使结果失效且不再回写状态。
- error 不自动重试，disabled 同时关闭 auto/manual/retry；Observer 缺失或宿主实现初始化失败时原生按钮降级仍可用。
- 手动加载/重试完成后焦点回到对应操作，自动加载不抢焦点；成功追加有可定制的 polite live announcement。
- 中英文状态、`aria-busy`、系统/ConfigProvider reduced-motion spinner、RTL、Dark、长文案换行与 forced-colors 按钮边界已覆盖。

## 何时使用

放在调用方列表尾部，用于游标或页码分页的“加载下一页”触发和状态表达。

## 何时不要使用

首屏加载、查询缓存、刷新和空状态不属于 InfiniteList；分别使用 Skeleton/Result、数据层、PullToRefresh 和 Empty。

## 结构与状态

状态为 idle/loading/error/complete。`hasMore=false` 是唯一 complete 事实源；内部 request id、AbortController、mounted flag 和同步 loading lock 管理并发、协作式取消与陈旧结果。

## 基础用法

```tsx
<List>{items.map(renderItem)}</List>
<InfiniteList hasMore={pageInfo.hasNextPage} loadMore={loadNextPage} />
```

## 受控与非受控

`hasMore` 受调用方控制；request 状态内部维护。组件不持有 items、cursor、页码或错误缓存。每次请求创建一个 AbortSignal；数据层需要把它继续传给 `fetch` 或其他可取消客户端。

## 表单集成

不适用。所有按钮固定为 `type=button`，不会提交父表单。

## Props

API 由 `InfiniteListProps` 生成。`loadMore({ signal, trigger })` 接收取消信号与实际入口；原有不声明参数的回调仍可直接使用。`threshold` 接受非负有限像素，异常值回退 250；`renderContent` 只替换视觉，原生加载/重试路径继续存在。

## Events

`onStatusChange` 报告去重状态和 `auto/manual/retry` trigger；外部完成不带 trigger。当前有效请求 reject 才调用 `onLoadError`；完成或卸载触发的 abort，以及随后到达的陈旧 rejection，均不作为本地加载错误报告。

## Ref 与命令式方法

ref 指向根 div；不公开命令式 load，避免绕过并发锁。业务主动加载应复用自己的数据层命令。

## 键盘操作

| 按键          | 行为                         |
| ------------- | ---------------------------- |
| Tab           | 进入当前可用的加载或重试按钮 |
| Enter / Space | 发起一次受锁保护的请求       |

手动加载或重试期间操作按钮会暂时退出 DOM；请求 settle 后，若仍有下一页且组件可用，焦点恢复到新的加载/重试按钮。Observer 自动加载不移动当前焦点。

## 触摸与手势

不识别手势；原生 120×44 按钮承担触摸入口，Observer 仅是预加载增强。

## 无障碍

loading 期间根使用 `aria-busy`，状态通过 atomic polite live region 公布；成功追加默认公布“已加载更多内容”，可用 `loadedAnnouncement` 注入包含新增数量的业务文案。error 仍提供可操作 retry；disabled 同时设置原生 disabled 和 `aria-disabled`。

## 动效

仅 loading spinner 旋转；`prefers-reduced-motion` 或 `ConfigProvider motion="reduced"` 下静止，状态变化无自定义过场。

## 主题与定制

状态 slots、labels、`renderContent` 与根 class/style 是稳定入口。颜色、圆角、间距使用 Token；forced-colors 保留按钮。

## SSR 与 Next.js

SSR 在默认 `autoLoad=true` 时也先输出可用的 idle 手动按钮，或按 `hasMore=false` 输出 complete，不创建 Observer。`hydrateRoot` 测试证明客户端结构无 mismatch，挂载后才发现最近滚动祖先并安装 Observer；浏览器缺失 Observer 时同一已 hydration 的原生按钮继续可用。

## RTL 与国际化

布局居中且无物理方向；内置中文和英文文案来自 ConfigProvider，可用各 label/content prop 覆盖。

## 浏览器与 WebView

IntersectionObserver 缺失、构造或 observe 失败时功能降级为按钮，不要求 polyfill。自动发现最近声明 `overflow-y:auto/scroll` 的祖先，不依赖首屏已经产生溢出；Chrome/WebView 70 与 iOS 13 基线支持 Promise、Observer 和 CSS，真实宿主滚动时序仍需复验。

## 边界情况与已知限制

- `loadMore` 必须返回 Promise；组件不猜测返回条数。
- disabled 只阻止新入口，不取消已发出的请求；`hasMore=false` 或卸载会 abort 当前 signal 并忽略陈旧结果。
- 取消是协作式的：若 loader 未把 signal 传给底层网络客户端，外部 I/O 仍可能继续，但不会回写组件状态或触发错误回调。
- error 必须由用户重试，不会形成 observer 重试风暴。
- 找不到可滚动祖先时 Observer 以 viewport 为 root。

## 性能预算

常数 DOM 和最多一个 Observer；每次只允许一个请求。数据渲染成本属于调用方列表。

- 官网 Next 运行时：本地 production build 在 390×844 下逐页验证 68 个组件页的 Light/Dark（136 场景）；主题恢复、H1/预览/API 结构、React `pageerror` / `console.error`（含 hydration mismatch）和 axe WCAG A/AA 均通过。

- Reduced motion/forced-colors/RTL: CSS 中 reduced-motion 停止旋转、forced-colors 使用系统按钮色；布局使用居中/无物理方向属性。自动 Storybook 矩阵覆盖继续适用，真机视觉仍见下方边界。

- Chromatic、real device: 待发布批次统一验证。
