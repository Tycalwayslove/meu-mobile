# Card

## 当前能力

- 非交互 div 容器，提供 media、leading、title、description、extra、body、footer 槽位和四档 padding。
- outlined/filled/elevated 三种表面；media 可选 aspect ratio；footer 默认保持任意内容布局，并可显式切换为可换行操作区。
- 保留 0/空字符串等有意内容；null/undefined/boolean/空数组/空 Fragment 不创建空 section。不把 Card 自动变成 button/link，避免嵌套交互冲突。
- RTL 使用逻辑 margin；forced-colors 保留边框。无动画。

状态为 `verification`；共置 Unit、SSR/hydration 与 Story 已覆盖核心结构，Chromium/WebKit 业务集成、Chromatic 和真机仍需以实际执行记录签字。

## 何时使用

用于商品、订单、账户等一组相关信息，并允许 header metadata、媒体和独立 footer actions。

## 何时不要使用

整行导航优先 Cell/Link；不要通过运行时向 Card 注入 onClick/role=button。整卡链接应由单一 Link 包裹且卡内不能再放按钮或链接。

## 结构与状态

根为 div；按需渲染 media/header/body/footer，并暴露相应 data slot。视觉 variant 与 padding 由根 data 属性记录。Card 无 focus/pressed/disabled 状态。

## 基础用法

```tsx
<Card title={<h2>订单摘要</h2>} description="今日创建" footer={<Button>查看详情</Button>}>
  3 件商品
</Card>
```

## 受控与非受控

不适用。Card 无内部状态。

## 表单集成

Card 不提交值；footer/body 内的真实表单控件按各自原生规则工作。不要让 Card 截获 submit/click。

## Props

API 由 `CardProps` 生成。title 是 ReactNode，不等于原生 title 属性；需要章节语义时传 h2–h6。mediaAspectRatio 使用 CSS aspect-ratio，旧 WebView 需媒体自身提供尺寸。`footerLayout="content"` 保持现有任意布局，只有显式 `actions` 才启用末端对齐与换行间距。

## Events

无专有事件，公开类型有意移除 onClick。内部链接/按钮事件独立冒泡，Card 不做代理、阻止或重复触发。

## Ref 与命令式方法

ref 指向根 div，仅用于测量/滚动定位；无 focus 或 click 命令。

## 键盘操作

| 按键 | 行为                                                  |
| ---- | ----------------------------------------------------- |
| Tab  | 只经过卡内真实链接、按钮或表单控件；Card 根不进入 Tab |

## 触摸与手势

Card 根没有手势。footer 操作必须使用至少 44×44 的 Button/IconButton；不要依赖整卡点击或 swipe。

## 无障碍

默认 div 不制造多余 landmark。title 只有调用方传原生 heading 才进入标题层级。媒体必须自带准确 alt；装饰媒体使用空 alt。操作区保持独立控件，禁止 button 内嵌 button/link。

## 动效

不适用。Card 无 hover/press/入场动画，reduced-motion 不需分支。

## 主题与定制

表面、边框、阴影、间距和字体来自 Meu Token；forced-colors 统一恢复 CanvasText 边框。稳定入口为 variant、padding、className/style 与 data slots。

## SSR 与 Next.js

纯 props render，无 browser API/effect；服务端按相同 slot 条件输出。媒体资源的 CLS 由 mediaAspectRatio 或媒体自身 width/height 控制。

## RTL 与国际化

header gap 与 extra 使用逻辑方向；actions footer 的 flex-wrap 在 RTL 下遵循文档方向。title/description/body 允许 anywhere 换行。

## 浏览器与 WebView

正式运行时支持继承 V2 矩阵：iOS Safari/WKWebView 15+ 与 Android Chrome/WebView 89+。Chrome 70 / iOS 13 只做构建产物语法扫描，不是运行时支持承诺；`aspect-ratio` 和 flex `gap` 均不能据此视为已验证。Card 的 header 间距和 action footer 使用逻辑 margin 降级，长词同时提供 `word-break` fallback；关键媒体仍需自身 `width`/`height`，不能只依赖 `mediaAspectRatio` 保证 CLS。

## 边界情况与已知限制

- 不提供交互根、加载态、选择态或 collapsible 行为。
- mediaAspectRatio 不裁剪子内容；媒体需自行 `object-fit` 和 100% 尺寸。
- actions footer 仅布局，不自动命名为 action group；复杂动作组由业务提供 fieldset/group 语义。
- loading/disabled 属于卡内真实控件的状态；Card 根不会代理、阻断或宣布这些状态。

## 性能预算

节点数与传入 slot 内容线性相关；Card 本身无监听、测量或 effect。超长列表应配合虚拟化容器。

- Bundle：Rollup tree-shaken ESM（React 与包 peer dependencies external）单一公开值 gzip 2225 B / 32768 B 预算，组合 Brotli 1964 B；共享样式由应用单独导入一次。

## 测试证据

- Unit: `Card.test.tsx` 覆盖静态根、0/空字符串与空 ReactNode、media、任意 footer 和独立 action。
- SSR/hydration: `Card.ssr.test.tsx` 直接断言服务端 slots，并在 jsdom hydrate 后检查 0 recoverable error、div 根和独立 button。
- Story: `Outlined` 有结构 play；`NarrowRtlContent` 提供 RTL、长词、窄宽、长 extra 和换行 actions 的人工/视觉检查场景。
- Reduced motion: Card 本身无动画。
- 尚无本目录可复核的 Chromatic 基线、真机读屏或 iOS 13/Chrome 70 运行时通过记录；不能从仓库级静态扫描推导这些结论。
