# PullToRefresh

## 当前能力

- 增强现有滚动边界，不创建固定高度或新滚动容器；默认先检测 root，再检测最近可滚动外层容器是否位于顶部。
- 状态为 idle、pulling、ready、refreshing、complete；阈值、阻尼、最大距离和完成停留均归一化。
- 单指纵向 Touch Events；横向、反向、多指、touchcancel/pointercancel、禁用切换和卸载都会交还或复位。
- focus 时显现的 44px 原生刷新按钮、busy 语义、原子 live status、失败回调与重复请求锁。

## 何时使用

用于移动列表或信息流的显式刷新增强；请求缓存、错误反馈和内容状态仍由业务持有。

## 何时不要使用

桌面唯一刷新入口、无滚动上下文、自动轮询或分页加载应使用普通 Button、查询策略或 InfiniteList。

## 结构与状态

root → focus-visible refresh button → status indicator → translated content。状态机 idle → pulling → ready → refreshing → complete → idle；短拉、取消和失败回到 idle。

## 基础用法

```tsx
<PullToRefresh onRefresh={() => query.refetch()}>
  <OrderList />
</PullToRefresh>
```

## 受控与非受控

不适用。瞬时手势和请求状态由组件持有；业务数据与错误由调用方持有。外部异步状态通过 `onRefresh` 返回的 Promise 接入：Promise pending 期间维持 refreshing 并严格去重，settle 后进入 complete 或 error 回调。组件不另设第二套 `refreshing` 布尔事实源，避免 Promise 与 prop 竞争。

## 表单集成

不适用。刷新不会提交、重置或修改表单字段。

## Props

API 表由 `PullToRefreshProps` 生成。`threshold/maxPullDistance/completeDelay/resistance` 会处理 NaN、Infinity、负值和倒置范围；`canPull` 用于复杂宿主边界判断。

## Events

`onStatusChange(status, details)` 只在状态实际变化时同步触发；`trigger: pull | keyboard` 表示造成该次状态转换的输入路径，方向无关的 idle 复位会省略。`onRefresh` 同步抛出或 reject 时调用 `onRefreshError(error)` 并复位；事件不可取消。

## Ref 与命令式方法

ref 指向根 `HTMLDivElement`，支持 React 19 callback-ref cleanup 和旧式 null callback；不公开命令式刷新，业务主动刷新应直接调用请求层。

## 键盘操作

| 按键          | 行为                              |
| ------------- | --------------------------------- |
| Tab           | 聚焦隐藏到 focus 时显现的刷新按钮 |
| Enter / Space | 通过原生 button 开始一次刷新      |

## 触摸与手势

只在单指、idle 且 root 或最近可滚动外层容器位于顶部时记录起点。4px slop 内不决定方向；越过 slop 后一次性锁定横向、向上或向下意图，并在真正锁定纵向前再次读取最新 scrollTop/canPull，避免落指后惯性滚动改变边界却仍被组件抢占。横向与向上手势不阻止滚动，确认向下后 non-passive touchmove 才阻止默认滚动。多指、touchcancel、pointercancel 和 disabled 切换取消；越过 resisted threshold 松手才刷新。

## 无障碍

手势不是唯一入口；原生 button 关联内容，refreshing 标记根和内容 `aria-busy`。indicator 使用 `role=status`、polite、atomic。失败的可操作提示由 `onRefreshError` 调用方提供。

## 动效

indicator/content 仅 transform；拖动期间过渡 0ms，复位使用 motion token。reduced-motion 压缩到 1ms。

## 主题与定制

稳定入口为 `renderIndicator`、`actionLabel`、根 style/className 和全局 Token。自定义 indicator 不得放交互内容。indicator 与键盘 action 支持长文案断行，键盘 action 限制在容器宽度内且保持 44px 最小目标；forced-colors 保留替代按钮边界。

## SSR 与 Next.js

组件是 client component，但初始 idle DOM 可服务端确定输出；render 不读取 window/document。`onRefresh` 与自定义 renderer 应保持 hydration 前结构稳定。

## RTL 与国际化

纵向手势不随 RTL 改变。默认中英文文案来自 ConfigProvider；`actionLabel/renderIndicator` 可覆盖。

## 浏览器与 WebView

使用 iOS 13 和 Chrome/WebView 70 已支持的 Touch Events、passive listener、Promise、transform 与 overscroll-behavior；后者在部分旧 iOS 只作渐进增强，确认手势后的 preventDefault 是仲裁事实源。尚无目标 App 真机证明。

## 边界情况与已知限制

- 不拥有滚动容器；shadow root、iframe 或自定义滚动模型必须传 `canPull`。
- 不提供 AbortSignal；请求取消由 transport 管理，卸载后只忽略结果。
- complete 期间允许再次刷新；refreshing 期间严格去重。

## 性能预算

每次 touchmove 只更新距离和必要状态；自定义 indicator 应保持轻量。组件不观察 DOM 尺寸或列表数据。

## 测试证据

- Unit/SSR/hydration：PullToRefresh 目录 3 个测试文件共 15 项通过，覆盖异常 threshold/resistance/maximum 规范化、短拉、显式边界 override、root 自滚动边界、touchstart 后 scrollTop 变化的二次仲裁、4px 落指抖动、键盘与外部 Promise pending 请求锁、reject/同步抛错/重试、多指/touchcancel/pointercancel/disabled、React 19 callback-ref cleanup，以及 pending result/complete timer 的卸载清理。SSR/hydration 证明 idle 根和 ID 复用、RTL/en-US/Dark/reduced-motion/长 action 稳定、0 recoverable/console error，且 hydration 后可进入 refreshing/busy。
- Story interaction：`Default.play` 验证原生替代按钮启动刷新；`ErrorAndRetry.play` 验证 reject → 可操作错误 → retry → complete；`LongLocalizedRtl.play` 验证 RTL/reduced-motion、无横向溢出和键盘 action 不低于 44px。当前 5 个 Story 将随主批统一重建后进入 Light、Dark、en-US、RTL、reduced-motion、200% 字体与 forced-colors 七环境门禁。
- Storybook 浏览器矩阵：本地扫描器在 390×844 视口验证 444 个 Story × 7 场景（Light、Dark、en-US、RTL、reduced-motion、200% 字体、forced-colors），共 3,108 个组合；有 play 的 Story 必须先返回 `storyFinished=success`，再运行 axe WCAG A/AA，结果为 0 违规、0 `pageerror`。
- 官网 Next 运行时：本地 production build 在 390×844 下逐页验证 68 个组件页的 Light/Dark（136 场景）；主题恢复、H1/预览/API 结构、React `pageerror` / `console.error`（含 hydration mismatch）和 axe WCAG A/AA 均通过。
- Bundle：Rollup tree-shaken ESM（React 与包 peer dependencies external）单一公开值 gzip 2820 B / 32768 B 预算，组合 Brotli 2431 B；共享样式由应用单独导入一次。
- SSR/hydration: `PullToRefresh.ssr.test.tsx` 覆盖 idle markup；独立 `PullToRefresh.hydration.test.tsx` 使用真实 `hydrateRoot` 证明服务端 idle 根节点复用、content id/`aria-controls` 稳定、RTL/en-US/Dark/reduced-motion 与长 action 保留、0 recoverable/console error，且 hydration 后键盘 action 能进入 refreshing/busy。隔离 `layout-contract.spec.ts` 提供对应移动浏览器路径。
- RTL / reduced motion / forced colors / 200%：逻辑方向、CSS 降级与长文案 Story play 已固化，随主批统一重建后执行七环境浏览器门禁。
- Mobile Chromium/WebKit E2E: Next production consumer 在双引擎使用真实可滚动 DOM 祖先（并断言 `scrollHeight > clientHeight`）与合成 Touch Events：`scrollTop > 0` 时向下手势不被阻止且不刷新；顶部横向意图不被阻止；4px 内横向/反向落指抖动后仍可锁定纵向；顶部纵向越过阈值会 `preventDefault` 并刷新；可控 pending 请求期间第二次 pull 被忽略且请求开始次数保持 1；`touchcancel` 复位距离且不刷新。原生替代按钮在请求中禁用，完成后经焦点 + Enter 触发下一次刷新并进入 `aria-busy=true`。这些是跨引擎可重复的 synthetic event 证据，不代表 trusted 真机触摸、iOS rubber-band 或 60 秒持续手势结果。
- Chromatic Light/Dark: stories 可采集，正式基线待确认。
- Real device: 待补。
