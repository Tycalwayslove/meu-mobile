# Space

## 当前能力

- 以 `inline-flex` 排列同级内容，`block` 可占满可用 inline width。
- 支持 horizontal/vertical、5 种 cross-axis 对齐、wrap，以及 9 档 Meu spacing token gap。
- horizontal 的开始方向跟随容器 `dir`，没有物理 left/right 布局 API。

当前状态为 `verification`；共置 SSR/hydration 已覆盖稳定容器与子控件复用，尚未完成观察档旧 WebView 与真机商用验收。

## 何时使用

用于按钮组、标签组、图标与文字等同级元素之间的稳定间距。gap 应来自设计 token，不用临时 margin 拼接相同结构。

## 何时不要使用

- 页面网格、复杂两栏布局或内容区骨架应使用专门布局容器。
- 不用多层 Space 模拟 Card、List 或表单结构。
- 需要分配剩余宽度、定位或滚动吸附时直接使用合适的 CSS layout。

## 结构与状态

结构是一个 div flex container 与调用方 children。没有交互状态；`data-direction`、`data-align`、`data-gap`、`data-wrap` 用于调试和视觉验收。

## 基础用法

```tsx
<Space gap={3} wrap>
  <Button>保存</Button>
  <Button variant="outline">取消</Button>
</Space>
```

## 受控与非受控

不适用。所有布局参数均直接由 Props 决定，不持有内部状态。

## 表单集成

Space 不参与表单值、校验或提交。它不会改变内部原生控件的 name、disabled、Tab 顺序或 FormData。

## Props

`gap` 只接受 `1 | 2 | 3 | 4 | 5 | 6 | 8 | 10 | 12`，分别映射 `--meu-space-{n}`。`direction` 默认 horizontal，`align` 默认 center，`gap` 默认 2，`block` 与 `wrap` 默认 false；其余属性透传原生 div。

## Events

只透传原生 div 事件，没有自定义事件或事件时序。

## Ref 与命令式方法

ref 指向外层 `HTMLDivElement`，只提供原生 DOM 能力。

## 键盘操作

| 按键 | 行为                                         |
| ---- | -------------------------------------------- |
| 无   | Space 不创建焦点；children 保持原有 Tab 顺序 |

## 触摸与手势

不定义手势，也不扩大 children 的触控目标。

## 无障碍

默认 div 没有额外 ARIA 语义，不改变 children 的读屏顺序。若内容本质是列表、工具栏或分组，应由调用方选择语义元素或设置准确角色，不能仅因视觉排列添加 ARIA。

## 动效

不提供内建动效，因此没有 reduced-motion 分支。children 尺寸变化导致的重排不会被 Space 动画化。

## 主题与定制

稳定定制面为 9 档 spacing token、方向、对齐、block 和 wrap。内部生成 class 不是公共 API；消费者 className 可用于容器级补充布局。

## SSR 与 Next.js

纯渲染组件，不读取浏览器全局，服务端与客户端输出一致。只有传入事件处理器时才需要 Client Component 边界。

## RTL 与国际化

horizontal 使用 flex row，顺序跟随 `dir=ltr|rtl`；start/end 是逻辑方向。Space 不含内建文案。改变 RTL 视觉顺序不会修改 DOM 顺序或读屏顺序，业务流程仍应使用符合语义的 children 顺序。

## 浏览器与 WebView

V2 完整支持档 iOS/WKWebView 15+、Android WebView/Chrome 89+ 均支持 flex gap。iOS 13–14 与 Chromium 79–83 属观察档，原生 flex gap 可能不可用；当前不注入 JS 检测或 margin polyfill，因此这些环境会保留排列但间距可能丢失。不要把旧语法扫描当作 flex gap 运行时证明。

## 边界情况与已知限制

- horizontal wrap 会按可用 inline width 换行；不可断行的 child 仍可能溢出。
- vertical wrap 只有容器存在明确 block-size 时才会产生新列，否则看起来与 nowrap 相同。
- `align=baseline` 依赖 children 自身 baseline；纯图形或复杂嵌套的结果由浏览器决定。
- Space 不克隆 children，也不为 Fragment 内部节点单独分配 API。
- 观察档旧 WebView 的 flex gap 没有内建 fallback。

## 性能预算

无状态、无 effect、无 children clone 和运行时测量。单实例只生成一个容器节点；正式发布前仍需记录样式增量 gzip。

## 测试证据

- Unit/SSR（本轮 5/5）: `Space.test.tsx` 覆盖顺序、方向、QA 属性、原生属性与 ref；`Space.ssr.test.tsx` 覆盖服务端顺序、真实 hydrateRoot 容器/按钮复用和 0 recoverable error
- Story interaction: `Wrapped` 验证方向、gap、wrap 与子项顺序；仓库门禁 `check-storybook-links` 本地验证 `play-fn 81/81`（81 个 Storybook title 均至少一个有意义 play）。
- Storybook 浏览器矩阵：本地扫描器在 390×844 视口验证 444 个 Story × 7 场景（Light、Dark、en-US、RTL、reduced-motion、200% 字体、forced-colors），共 3,108 个组合；有 play 的 Story 必须先返回 `storyFinished=success`，再运行 axe WCAG A/AA，结果为 0 违规、0 `pageerror`。
- 官网 Next 运行时：当前 production build 在 390×844 下逐页验证 68 个组件页的 Light/Dark（136 场景）；主题恢复、H1/预览/API 结构、React `pageerror` / `console.error`（含 hydration mismatch）和 axe WCAG A/AA 均通过。
- Bundle：Rollup tree-shaken ESM（React 与包 peer dependencies external）单一公开值 gzip 1260 B / 32768 B 预算，组合 Brotli 1128 B；共享样式由应用单独导入一次。
- SSR/hydration: 共置测试直接验证 `gap=3`、wrap、子项顺序以及容器/按钮节点复用；既有隔离 Next 16 场景存在，本轮未重复执行该全局场景
- RTL: `RightToLeft` Story 进入全库 RTL 矩阵；独立 layout contract 在 Chromium/WebKit 中断言 RTL 视觉顺序、12px token gap、换行和 baseline 对齐
- Reduced motion: 不适用；没有内建动效
- Mobile Chromium/WebKit E2E: `composes layout, icon action, custom portal and hidden accessible text` 在两种引擎断言 token gap、wrap 与内部按钮键盘操作
- Chromatic Light/Dark: 5 组 Story 可构建，显式 Light/Dark 快照矩阵待补
- Real device: 待补
