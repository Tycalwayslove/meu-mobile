# SideNav

## 当前能力

SideNav 用一套数据 API 覆盖两种明确语义：存在任一 `content` 时渲染 APG vertical tabs；全部 item 都没有 `content` 时渲染原生侧边导航。当前版本支持受控/非受控选择、automatic/manual tab 激活、禁用项、动态 items、重复 key 归一、激活项入视、长 rail、sticky 边界、RTL、badge、root ref、SSR 与 hydration。

本组件仍处于 `verification`，代码和自动化契约已完成 V2 加固，Chromatic 最终基线及 iOS/Android 真机读屏记录留到全库统一验收。

## 何时使用

- 同一页面内切换数量较多的同层级内容分类，例如商品类目或设置分区。
- 在窄屏内容区左侧提供局部导航，并让右侧内容保持主要阅读宽度。
- 需要纵向键盘 tablist、长列表滚动或随页面保持可见的分类 rail。

## 何时不要使用

- 一级页面入口使用 TabBar；少量水平切换使用 Tabs 或 SegmentedControl。
- 树形层级、展开/收起、异步子节点或多选路径使用 TreeSelect。SideNav 不实现嵌套导航。
- 数百个可搜索分类不要一次放入 SideNav，应先用搜索、分段加载或虚拟列表缩小集合。

## 结构与状态

模式由去重后的 items 决定，`content={null}` 也表示显式进入 tabs 模式。

| 模式       | 触发条件                   | DOM 与语义                                            | 键盘模型                      |
| ---------- | -------------------------- | ----------------------------------------------------- | ----------------------------- |
| Tabs       | 任一 item 定义 `content`   | `tablist → button[tab]`，随后是关联的 `tabpanel`      | 单一 roving Tab stop + 上下键 |
| Navigation | 所有 item 都未定义 content | `nav → ul → li → a/button`，当前目的地 `aria-current` | 原生 Tab 顺序，不拦截方向键   |

Tabs 模式下 item 的 `href`、`target`、`rel` 不生效，避免 tab 同时承担页面导航。Navigation 模式下有 `href` 的 item 始终保持 anchor identity；无 `href` 时为 `type="button"` 动作。

## 基础用法

页面内垂直 tabs：

```tsx
<SideNav
  aria-label="商品分类"
  defaultValue="food"
  items={[
    { key: "featured", label: "精选", content: <FeaturedProducts /> },
    { key: "food", label: "食品", badge: 3, badgeLabel: "3 项更新", content: <Food /> },
    { key: "service", label: "服务", content: null, disabled: true }
  ]}
/>
```

原生导航目的地与动作可以共存：

```tsx
<SideNav
  aria-label="商品频道"
  value={channel}
  items={[
    { key: "all", label: "全部", href: "/categories" },
    { key: "food", label: "食品", href: "/categories/food" },
    { key: "saved", label: "已收藏" }
  ]}
  onChange={(key) => {
    setChannel(key);
  }}
/>
```

客户端路由可以在 `onChange` 中取消原生跳转，再交给 router；服务端首屏仍保留真实 `href`：

```tsx
<SideNav
  items={routes}
  value={pathname}
  onChange={(key, event) => {
    if (event.currentTarget instanceof HTMLAnchorElement) {
      event.preventDefault();
      router.push(event.currentTarget.href);
    }
  }}
/>
```

## 受控与非受控

`value !== undefined` 即受控，包含 `null`。受控的 `null`、未知 key 或 disabled key 不选择任何 item/panel；Tabs 模式仍把首个 enabled item 保留为键盘入口。点击或键盘激活只发出 `onChange`，可见选择等待调用方更新 `value`。

省略 `value` 时为非受控。有效 `defaultValue` 作为首选，否则选择首个 enabled item。当前非受控 item 被删除或禁用时，会归一到新的首个 enabled item；旧 key 之后重新出现不会让选择跳回。

## 表单集成

SideNav 不是表单字段，不提供 `name`、FormData 或 form adapter。Navigation 模式的动作按钮固定为 `type="button"`；Tabs panel 内可以放表单，但其状态、校验与提交完全由 panel 内容和业务表单拥有。

## Props

| Prop              | 类型                               | 默认值       | 说明                                                                  |
| ----------------- | ---------------------------------- | ------------ | --------------------------------------------------------------------- |
| `activationMode`  | `"automatic" \| "manual"`          | `automatic`  | 只影响 Tabs 模式；manual 需 Enter/Space 激活                          |
| `defaultValue`    | `string`                           | 首个 enabled | 非受控初始 key                                                        |
| `destroyInactive` | `boolean`                          | `false`      | Tabs 模式卸载 inactive panel，会丢失其中局部状态                      |
| `items`           | `readonly SideNavItem[]`           | 必填         | 有序数据；重复 key 只保留第一次出现的 item                            |
| `onChange`        | `(key, event) => void`             | 无           | 新 key 激活后调用；event 为 anchor/button 点击或 tab 键盘事件         |
| `sticky`          | `boolean`                          | `false`      | 让 rail 相对最近滚动祖先 sticky，并把长列表限制在可用 viewport 内     |
| `stickyOffset`    | `CSSProperties["insetBlockStart"]` | `0`          | sticky rail 的逻辑 block-start 偏移，例如 `56` 或 `"var(--header-h)"` |
| `value`           | `string \| null`                   | `undefined`  | 受控 active key                                                       |
| `ref`             | `Ref<HTMLDivElement>`              | 无           | 指向 root div                                                         |
| 其余属性          | `HTMLAttributes<HTMLDivElement>`   | 无           | 透传到 root；`aria-label/labelledby` 专用于内部 nav/tablist           |

### SideNavItem

| 字段         | 类型               | 说明                                                                      |
| ------------ | ------------------ | ------------------------------------------------------------------------- |
| `key`        | `string`           | 稳定选择值与 DOM identity；同一 items 内应唯一                            |
| `label`      | `ReactNode`        | 可见名称；长文本会换行，不通过 CSS 截掉语义                               |
| `ariaLabel`  | `string`           | label 不是可读文字时提供；使用后应自行包含 badge 的重要状态               |
| `content`    | `ReactNode`        | 定义后整个 SideNav 进入 Tabs 模式                                         |
| `disabled`   | `boolean`          | 从选择和 tabs 键盘循环移除；disabled link 无 href 且不可聚焦              |
| `badge`      | `ReactNode`        | 短计数或状态                                                              |
| `badgeLabel` | `string`           | badge 的完整读屏文本，例如“12 项待处理”                                   |
| `href`       | `string`           | Navigation 模式原生链接；Tabs 模式忽略                                    |
| `target`     | 原生 anchor target | Navigation 链接浏览上下文                                                 |
| `rel`        | `string`           | Navigation 链接关系；`target="_blank"` 且未提供时补 `noopener noreferrer` |

## Events

`onChange(key, event)` 只在 enabled item 产生不同 key 时触发；重复激活当前 key 不触发。

- Tabs automatic：方向键移动焦点时同步触发。
- Tabs manual：方向键只移动焦点，Enter/Space 才触发。
- Navigation：原生 anchor/button 点击触发。对 anchor 调用 `event.preventDefault()` 可接管客户端路由。
- 受控模式不会因事件自行改变可见选择；非受控模式会立即更新。

## Ref 与命令式方法

`ref` 指向包含 rail 和 panels 的 root `HTMLDivElement`。`className` 追加内部 class，`style`、`id`、`data-*`、root ARIA 和事件属性正常透传。`aria-label` / `aria-labelledby` 会落到实际 `nav` 或 `tablist`，不会制造额外可访问性层级。

组件不公开命令式切换、滚动或路由方法；状态由 Props 驱动，路由由原生 href 或应用 router 拥有。

## 键盘操作

Tabs 模式遵循 vertical tablist：

| 按键                | 行为                                                 |
| ------------------- | ---------------------------------------------------- |
| ArrowDown / ArrowUp | 循环移动焦点并跳过 disabled；automatic 同时激活      |
| Home / End          | 移至首个/末个 enabled item                           |
| Enter / Space       | manual 模式激活当前聚焦 tab                          |
| Tab                 | rail 只有一个 roving Tab stop；随后进入 active panel |

Navigation 模式保持浏览器原生 Tab/Shift+Tab 和 Enter/Space 行为，不把 landmark 伪装成 composite widget，也不拦截方向键。上下键在 RTL 中均不镜像。

## 动态 items、重复 key 与焦点恢复

- 重复 key 会确定性地“第一次出现者胜出”，避免 React key、选择和焦点映射冲突；生产数据仍应在上游保证唯一。
- 删除、禁用或替换当前聚焦 item 时，只在焦点原本属于本实例且浏览器把焦点退回 body 的情况下恢复到 active/首个 enabled item。
- 普通 rerender、另一个 SideNav 更新或用户已把焦点移到外部时不会抢回焦点。
- 所有 item 都 disabled 或 items 为空时不创建伪焦点目标。

## 触摸与手势

每个 rail item 至少 52px 高、104px 宽；组件不注册 touch/pointer 手势，也不阻断页面滚动。长 rail 使用浏览器原生纵向滚动与惯性，选择由点击或键盘完成。

## 长列表、激活项入视与 sticky

rail item 最小高度 52px、宽度 104px，达到移动触控目标要求。标签允许 CJK、RTL、emoji 和长单词自然换行；badge 保持独立尺寸。rail 使用原生惯性纵向滚动，不注册 touch/pointer 拦截器。

active key、items identity 或 rail/item 尺寸变化时，组件先比较两者几何，只调整 rail 自身的 `scrollTop`，不会平白移动页面。尺寸变化优先使用 ResizeObserver，不支持时监听 window resize；不可测量的测试/旧环境才降级调用 `scrollIntoView({ block: "nearest" })`。

`sticky` 将 rail 置于最近滚动祖先的 block-start，并用 `100vh`（支持时升级到 `100dvh`）减去 `stickyOffset` 形成最大高度。调用方必须让祖先拥有足够滚动范围；`overflow: hidden`、transform 或错误的滚动祖先会改变原生 sticky 边界，组件不会改写页面布局。

## 内容关联与卸载

Tabs 模式用 `useId` 加 key 的 Unicode code point 后缀生成稳定的 `tab.id ↔ aria-labelledby ↔ panel.id` 双向关联，因此插入或重排 items 不会改变现有 key 的关系。active panel 进入 Tab 顺序，inactive panel 使用 `hidden`。`destroyInactive=false` 保留所有 panel DOM 和局部状态；设为 true 只挂载 active panel。

如果 items 混合“有 content”和“无 content”，组件仍为每个 tab 建立 panel，无 content 项得到空 panel。这是兼容行为，不建议用来混合页面导航；应统一提供 content，或拆成纯 Navigation SideNav。

## 无障碍

- Tabs：`tablist`、`tab`、`tabpanel`、`aria-selected`、`aria-controls` 与 roving tabindex 完整关联。
- Navigation：真实 `nav/ul/li`；目的地用 anchor，动作才用 button，当前项使用 `aria-current="page"`。
- Disabled anchor 保留 `<a role="link">` identity，但移除 href、设 `aria-disabled` 和 `tabIndex=-1`；disabled button 使用原生 `disabled`。
- active 状态由背景、字重和完整内轮廓共同表达，不只依赖颜色；disabled 不只降低 opacity。
- 始终可见 2px focus outline；forced-colors 下使用 Canvas/Highlight/GrayText 保留边界、选择与禁用状态。
- badge 的业务含义不能只写成视觉缩写，应提供 `badgeLabel` 或在 `ariaLabel` 中给出完整名称。

## 动效

选择态只过渡背景和文字颜色，不动画布局、宽高或滚动位置。时长使用 motion Token；`prefers-reduced-motion: reduce` 降至 1ms，ConfigProvider 的 `motion="reduced"` 会把 Token 设为 0ms。

## 主题与定制

颜色全部来自 surface/subtle/ink/muted/accent/danger/border Token，支持 Light/Dark 与 forced colors。稳定的 data 属性可以用于测试和状态观测；内部生成 class 不是定制 API。

## RTL 与国际化

rail 边界、padding 与 sticky offset 使用逻辑属性，DOM `dir="rtl"` 时自动镜像；完整选择轮廓无需方向覆盖，纵向按键不镜像。可见 label、badge 文案和 `ariaLabel` 由调用方本地化，组件只为整个 rail 提供中英文缺省名称。

## SSR 与 Next.js

- 初始 items/value 一致时，`useId`、native element identity、disabled href 缺省和 sticky style 均可确定 hydration。
- Navigation 链接在服务端即输出真实 href；disabled 链接服务端就没有可导航 URL，不存在 hydration 前短暂可点击窗口。
- 组件不导入 Next Router；App Router/Pages Router 都通过 href 或 `onChange + preventDefault` 接入。

## 浏览器与 WebView

- 正式支持基线为 iOS Safari/WKWebView 15+ 与 Android Chrome/WebView 89+。逻辑属性、overscroll 和 dynamic viewport 不支持时保留可用导航与 100vh fallback，局部滚动细节可能降级。

## 边界情况与已知限制

- 不支持 nested items、折叠分组、异步 children、搜索或虚拟化；这些能力属于 TreeSelect/VirtualList。
- 模式由 content 自动推断，目前没有运行时 mode 切换动画；跨模式切换会替换 rail 语义节点，并在原焦点仍属本实例时恢复到对应 key。
- `destroyInactive` 会卸载表单输入、滚动位置和组件局部状态，调用方需要把应保留的数据提升。
- 组件不判断业务权限或 loading；不可用目的地应使用 disabled，异步加载放在 panel 内处理。
- sticky 受 CSS 原生 containing block 规则约束，不解决页面固定 NavBar/TabBar 的占位，`stickyOffset` 应由布局层提供。

## 性能预算

选择、去重和渲染均为 O(items)。默认 Tabs 会保留全部 panel DOM；`destroyInactive` 可降低 DOM 成本，但以丢失 inactive 状态为代价。推荐几十项以内；大集合先缩小数据，而不是把业务虚拟化隐藏在导航组件中。

- Bundle：Rollup tree-shaken ESM（React 与包 peer dependencies external）单一公开值 gzip 4923 B / 32768 B 预算，组合 Brotli 4349 B；共享样式由应用单独导入一次。
