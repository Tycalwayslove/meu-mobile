# Popup

## 当前能力

- 四方向 Portal 浮层，支持受控/非受控 open、Mask、滚动锁、焦点圈定/恢复、Escape 和关闭按钮。
- 支持自定义 portal container、forceMount、safe area、initial/return focus ref；打开时切换容器会重新绑定焦点圈定。
- 用户关闭意图提供 `mask | escape | close-button` reason；程序化 prop 变化不发事件。退出动画结束后卸载，退出中重开会取消卸载。
- Portal layer 逐项继承最近 ConfigProvider/ThemeProvider 的 locale、dir、theme、motion、语义 Token 与原生 `color-scheme`。

## 何时使用

作为需要阻断背景交互的通用模态面板基础。业务级 Dialog、Picker、ActionMenu 应优先使用对应高层组件。

## 何时不要使用

非模态提示使用 Popover/Toast；复杂拖拽与 snap 使用 BottomSheet；不在 Popup 内重复实现路由、数据请求或表单状态机。

## 结构与状态

Portal layer → optional Mask → dialog panel → optional close button → body。DOM 的 `data-state` 为 open/closed；打开时通过两帧从 closed 过渡到 open，关闭时立即进入 inert/aria-hidden 的 closed 视觉态，并在 presence 窗口结束后卸载。

## 基础用法

```tsx
<Popup aria-label="筛选条件" open={open} onOpenChange={setOpen}>
  <FilterForm />
</Popup>
```

## 受控与非受控

受控使用 `open/onOpenChange`，非受控使用 `defaultOpen`。受控模式下关闭意图只回调，不自行改变 open；调用方拒绝请求时 Popup 保持打开、锁滚动并圈定焦点。外部程序化开关不反向调用 `onOpenChange`。退出中重开会取消待执行卸载，重新进入并继续焦点与滚动锁。

## 表单集成

Popup 不持有表单值。关闭前是否丢弃草稿由组合组件决定；提交按钮应在表单内使用原生 submit。

## Props

API 由 `PopupProps` 生成。调用方必须二选一提供 `aria-label` 或 `aria-labelledby`；重要行为 Props 包括 container、mask、lockScroll、closeOnEscape、closeOnMaskClick、restoreFocus、initialFocusRef、returnFocusRef、forceMount 和 safeArea。role、aria-modal、aria-hidden、hidden、inert 和 tabIndex 由组件固定管理，不是覆盖入口。

共享 `OverlayContainer`、`OverlayDismissReason` 与 `OverlayOpenChangeDetails` 类型由本页归档；具体组件可以扩展 reason，但不得改写基础 `mask | escape | close-button` 含义。

## Events

`onOpenChange(open, details)` 仅在组件请求变化时调用。当前关闭 reason 为 `mask`、`escape`、`close-button`。Mask 必须完成原生 click 才产生 mask reason；pointercancel 不关闭。程序化 open 变化不反向发事件，也没有 programmatic reason。

## Ref 与命令式方法

ref 指向 dialog panel。`initialFocusRef` 只有在指向面板内可见元素时生效，否则回退到首个 tabbable 元素，再回退到 panel。`returnFocusRef` 优先于打开前捕获的焦点；`restoreFocus=false` 关闭自动恢复。不要依赖内部 DOM。

## 键盘操作

| 按键            | 行为                       |
| --------------- | -------------------------- |
| Escape          | `closeOnEscape` 时请求关闭 |
| Tab / Shift+Tab | 在最上层 Popup 内循环焦点  |

## 触摸与手势

Mask 点击可选关闭；pointercancel 不合成 click，因此不会关闭。面板本身不定义拖拽。关闭按钮目标为 44×44，内部滚动区使用原生触摸滚动和 overscroll contain；旧 iOS 忽略该增强时，body lock 仍阻止页面主滚动，橡皮筋边界需真机验证。

## 无障碍

面板使用 `role="dialog"`、`aria-modal="true"` 并强制可访问名称。打开时圈定焦点并通过共享引用计数管理器把背景 siblings 设为 inert/aria-hidden；嵌套模态只暴露栈顶，自定义 Portal 容器会沿祖先路径隔离背景，关闭后精确恢复原属性。打开时更换 HTMLElement 容器会重建 panel ref 和焦点圈定；resolver 返回目标变化时必须传入新的 resolver identity。Popover focus branch、由 `aria-controls` 关联的 NumberKeyboard 与 Toast live region保持可达；真实读屏浏览模式仍需真机验证。

## 动效

bottom/top/right/left 分别从对应物理边缘沿 transform 进入。标准进入/退出 Token 为 180/140ms，缓动为 standard；presence 保留 160ms，覆盖退出动画。退出中重开会取消卸载。prefers-reduced-motion 将 panel 与 Mask 过渡缩至 1ms；presence 仍保留惰性 DOM 到 160ms，但关闭后立即 inert/aria-hidden，不再交互。

## 主题与定制

公开定制为 position、maskOpacity、safeArea、close button、container、className/style 与全局 Token。z-index 由 overlay 层级统一治理。forced-colors 去除浮层阴影并恢复 CanvasText panel 边界、ButtonText 关闭按钮边界与原生 focus outline。

## SSR 与 Next.js

Portal 在 SSR 和首次 hydration 内联输出，客户端挂载后移到 body 或目标容器。Node SSR 已证明 closed 非 forceMount 不输出、closed forceMount 输出 hidden/inert、open 不解析 lazy target；JSDOM hydrateRoot 已证明 open body Portal 移动无 recoverable error。服务端与首次客户端必须提供一致的 open、forceMount、position 和可访问名称。

## RTL 与国际化

关闭 label 从 ConfigProvider locale 获取，也可显式覆盖。关闭按钮在 RTL 下移到左上角。left/right position 始终表示物理方向；产品需要 start/end 时必须在 API 评审后增加，不能静默翻转。

## 浏览器与 WebView

Chrome 70 与 iOS 13 可解析实现；不依赖 dvh、CSS logical inset 或 transitionend。旧浏览器不支持 overscroll-behavior 时只失去滚动链增强。仍需真机验证 iOS body lock、软键盘/visual viewport、返回焦点、嵌套 Portal 和浏览器后退键组合。

## 边界情况与已知限制

- 当前 `aria-modal` 固定为 true，不适合非模态用法。
- 背景隔离只管理同一 Document；跨 iframe/ShadowRoot 仍需宿主显式分区。
- container 支持当前 Document 中的 HTMLElement；跨 Document/ShadowRoot 尚未声明支持。lazy resolver 的目标变化必须伴随新函数 identity。
- Popup 不监听 visualViewport；含输入框的 bottom panel 可能被旧 WebView 软键盘遮挡，复杂键盘避让使用 BottomSheet 或业务布局。

## 性能预算

关闭且非 forceMount 时不保留内容；全局监听和 body lock 必须引用计数并在卸载时清理。

- Unit: `Popup.test.tsx` 覆盖关闭原因与 mask pointercancel、无 Mask 模态隔离、initial focus/圈定/恢复、forceMount 退出、退出中重开、动态 Portal 容器、栈顶 Escape、滚动锁、嵌套背景隔离、自定义容器属性恢复、关联 NumberKeyboard 与 body Portal hydration；`overlayHooks.test.tsx` 覆盖 tabbable 顺序与 isolation 引用计数。
- SSR: `Popup.ssr.test.tsx` 覆盖 closed/open/forceMount、固定 dialog 语义和 lazy container 不在服务端求值。
- Story interaction: `Bottom.play` 验证打开、可访问对话框、关闭和焦点恢复；`check-storybook-links` 本地验证 play-fn 为 81/81（按 Storybook title 计）
- Storybook 浏览器矩阵：本地扫描器在 390×844 视口验证 444 个 Story × 7 场景（Light、Dark、en-US、RTL、reduced-motion、200% 字体、forced-colors），共 3,108 个组合；有 play 的 Story 必须先返回 `storyFinished=success`，再运行 axe WCAG A/AA，结果为 0 违规、0 `pageerror`。
- 官网 Next 运行时：本地 production build 在 390×844 下逐页验证 68 个组件页的 Light/Dark（136 场景）；主题恢复、H1/预览/API 结构、React `pageerror` / `console.error`（含 hydration mismatch）和 axe WCAG A/AA 均通过。
- Bundle：Rollup tree-shaken ESM（React 与包 peer dependencies external）单一公开值 gzip 5739 B / 32768 B 预算，组合 Brotli 5162 B；共享样式由应用单独导入一次。
- SSR/hydration: Popup Node SSR 与 JSDOM hydrateRoot 已独立覆盖；隔离 Next production 以服务端 open 状态在 Chromium/WebKit 完成组合 hydration，0 `pageerror`、0 `console.error`。
- RTL: RightToLeft Story 覆盖 close button 布局与物理 left position；浏览器矩阵截图仍待重跑。
- Reduced motion: CSS 1ms 降级已实现；新增 Stories 尚未进入扩展浏览器矩阵。
- Mobile Chromium/WebKit E2E: 打开、focus trap、Escape/关闭、焦点恢复、scroll lock 与 action 链路通过；隔离的 `overlay-lifecycle.spec.ts` 覆盖嵌套 Provider Portal 配置/Token、开态迁移容器、mask pointercancel、退出中重开，以及迁移/中断前后仅一个 Popup layer、焦点圈定和 scroll lock；读屏浏览模式留待真机。
- Overlay boundary gate: Popup 与其余 7 个直接 Portal 消费者受静态扫描约束；双移动引擎验证 locale、RTL、dark、reduced-motion、`color-scheme` 与语义色 Token 在 Portal 目标中完整保留。
- Chromatic Light/Dark: Figma 与 stories 已有基线，待显式矩阵
- Real device: 待补
