# Dialog

## 当前能力

模态告知、确认和短交互容器，支持 alertdialog/dialog 语义、异步操作、操作失败留场、自动布局、Mask、Escape、焦点圈定/恢复、滚动锁、Portal 与 Provider 作用域命令式 API。打开期间切换 Portal 目标时，焦点圈定会随面板迁移。

## 何时使用

用于必须明确响应的告知、二次确认或短小输入；危险操作使用 danger action，并优先聚焦较安全操作。

## 何时不要使用

长表单、连续流程和大量选择使用 BottomSheet/Picker；非模态锚定内容使用 Popover；短暂反馈使用 Toast。

## 结构与状态

`Portal → layer + Mask + panel[role=alertdialog|dialog] → content + native actions`。状态包括 open/closed、pending action、horizontal/vertical actions。

## 基础用法

```tsx
<Dialog
  open={open}
  title="删除订单？"
  description="删除后无法恢复。"
  actions={[
    { key: "cancel", label: "取消" },
    { key: "delete", label: "删除", tone: "danger" }
  ]}
  onOpenChange={setOpen}
/>
```

## 受控与非受控

`open` 存在时受控，组件只发布关闭意图，父级必须回写 `open=false`；否则使用 `defaultOpen` 并在发布意图时同步内部状态。父级直接改变 `open` 不触发 `onOpenChange`。命令式 `alert/confirm/show` 必须放在 DialogProvider 内，并保留当前 locale、theme 与 Portal 上下文。

## 表单集成

Dialog 不是字段 adapter；可在 `role="dialog"` body 中放短表单，但值、校验、提交与脏状态由业务/`@meu/form-react` 持有。操作按钮固定非 submit。

## Props

默认 `role=alertdialog` 且必须有 description；普通交互显式使用 `role=dialog`。`actionLayout=auto` 在 1–2 项横排、3+ 项纵排。actions key 必须唯一；第一个 enabled `autoFocus` action 优先，否则聚焦第一个 enabled action。关闭 Mask 默认 false，Escape、scroll lock 与 focus restore 默认 true。`container=null` 原地渲染；resolver 改变返回目标时必须同时提供新的函数 identity，使焦点圈定重新绑定。

## Events

`onOpenChange` 只报告用户关闭意图，原因是 escape、mask 或 `{reason:"action",actionKey}`。任一 action pending 时，重复 action、Escape 和 Mask 关闭全部冻结；成功且 `closeOnPress!==false` 才发布关闭。`action.onPress` 返回 false 或 reject 保持打开；当前会话的 reject 交给 `onActionError`，未提供回调时也会被组件收口，不产生未处理 Promise。只有已经提交的关闭、重开或卸载会废弃旧 action；React 放弃的并发 render 不会改变当前会话。

## Ref 与命令式方法

声明式 ref 指向 panel。`useDialog()` 提供 `alert():Promise<void>`、`confirm():Promise<boolean>`、`show():controller` 与 `clear()`。confirm 仅在确认 action 成功时得到 true；取消、Escape、Mask、clear 或 Provider 卸载得到 false。action 返回 false 或 reject 时弹窗和 Promise 都保持待决，允许用户重试。Provider 正常关闭时先提交 `open=false`，使模态层退出可访问树并释放滚动锁，再结算 alert/confirm Promise；退出动画对应的 DOM 移除可以在 `await` 恢复后完成。Provider 卸载则在 cleanup 中结算。controller.close 幂等。

## 键盘操作

Tab/Shift+Tab 在最上层 Dialog 内循环；Escape 在允许且无异步 pending 时关闭；原生按钮支持 Enter/Space。

## 触摸与手势

操作目标至少 44px；遮罩关闭默认禁用，避免移动端误触。组件无滑动手势。

## 无障碍

标题生成 aria-labelledby；alertdialog description 生成 aria-describedby；panel `aria-modal=true`。异步期间 `aria-busy=true` 并禁用其他入口；背景内容由共享 modal manager 设置 inert/aria-hidden。嵌套时只有顶层接收 Escape 和焦点，body scroll lock 按层计数；上层关闭后仍打开的下层继续持有锁。外部关闭、Portal 迁移、重开与卸载均有自动化回归。

## 动效

layer opacity + panel opacity/transform；reduced-motion 取消 transform 并缩短到 1ms，pending 不依赖动画。

## 主题与定制

使用 surface/ink/muted/border/shadow 与 Button tokens；forced-colors 使用 Canvas/CanvasText。className/style 作用于 panel。

## SSR 与 Next.js

Portal SSR 原地输出稳定关联，useId 保证标题/说明 ID；服务端不求值 lazy container，hydration 后无 recoverable error 地迁移到目标容器。关闭态不输出；`forceMount` 关闭态输出 hidden + inert + aria-hidden。Provider 不使用模块级 createRoot。

## RTL 与国际化

DOM 中的操作顺序保持业务数组顺序，不猜测取消/确认；横排视觉方向遵循 RTL 的逻辑行方向。内置 alert/confirm 文案支持 zh-CN/en-US。Portal layer 复制 ConfigProvider 的 dir、lang、theme 与 motion 边界。

## 浏览器与 WebView

兼容 Chrome/WebView 70+、iOS 13+；长标识符同时提供旧内核 `word-break: break-word` 与现代 `overflow-wrap: anywhere`，小高度视口降低外层 padding，内容区独立滚动。真实软键盘视口待最终双引擎验证。

## 边界情况与已知限制

Dialog 不校验重复 action key；调用方必须保证唯一。不要把 Dialog 作为 Popup 内的普通内容嵌套；若业务确需模态叠层，应让两层都保持独立 Portal，由共享 focus-trap 栈决定顶层。若多个 Dialog 在同一次 React 提交中同时挂载，上层关闭会恢复各自打开时捕获的目标，不额外猜测并聚焦下层 action；优先串行打开。组件不提供拖拽、手势关闭或软键盘避让。

## 性能预算

O(actions)，无布局测量；关闭记录仅为退出动画短暂保留。
