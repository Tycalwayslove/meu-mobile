# Slider

## 当前能力

- 原生 `input[type="range"]` 单值滑块，保留浏览器触摸拖动、键盘、表单、约束与读屏语义。
- 受控/非受控、原生 form reset、ref、name/form/disabled、三档尺寸、error、可选值输出、格式化输出与装饰性 marks。
- `readOnly` 输出静态 `meter` 语义和不可操作的轨道，同时用 hidden input 保留 FormData 与 input ref；它不再依赖对 range 无效的原生 readonly 属性。
- min/max 有限值会排序；max 不在步长网格上时使用最后一个可达值作为有效上限。渲染值、原生 max、进度、marks 和回调按同一有效范围与正 step 对齐，非法 step 回退为 1。
- `onChangeComplete` 只在一次真实改变的 pointer 或值变更键交互结束时触发一次；取消 pointer、无变化抬手和陈旧事件不会误报。
- track、marks 与原生 range direction 支持 RTL；焦点、forced-colors 和 44px 最小触控高度有明确降级。

当前为 V2 `verification`。单元、SSR、Story、本地 axe 与全库浏览器场景矩阵已建立；Next-H5 集成场景已在移动 Chromium/WebKit 中验证键盘改值、可信鼠标 pointer 拖动、单次完成回调和表单提交。合成 pointercancel 的收敛已验证，但真实触摸取消、组件专属真机读屏和最终 Chromatic 视觉审批尚未完成，因此不能标记为 commercial。

## 何时使用

- 音量、距离、预算、完成度等连续或准连续的单值选择，用户更重视相对位置而非精确录入。
- 候选范围稳定、上下界明确，并允许通过键盘细调的场景。

## 何时不要使用

- 必须精确录入、复制或比较数字时使用 Stepper/TextInput；少量离散选项使用 Radio/Selector。
- 双端区间不是当前契约，不用两个 Slider 叠加模拟；应使用专门 RangeSlider。
- marks 不是可点击选项或读屏列表；需要离散且有标签的选择时不要依赖 marks。

## 结构与状态

交互态结构为原生 range、可选 output 和 presentation-only marks；只读态由外层 meter、aria-hidden 的静态 range 轨道与 hidden form input 组成。状态为 default、focus、error、readOnly、disabled，另有 small/medium/large。根节点暴露 `data-meu-component="slider"`、`data-size`、`data-state`；内部 class 不是稳定 API。

## 基础用法

```tsx
<Field label="配送距离" description="0 到 20 公里">
  <Slider
    name="distance"
    min={0}
    max={20}
    step={1}
    defaultValue={5}
    showValue
    formatValue={(value) => `${value} km`}
  />
</Field>
```

只读且随表单提交：

```tsx
<Slider aria-label="审核后预算" name="approvedBudget" value={65} readOnly showValue />
```

## 受控与非受控

- 传 `value` 为受控；显示值会按 bounds/step 规范化，父级仍拥有业务事实源。
- 不传 `value` 时使用内部状态；`defaultValue` 初始化且作为原生 form reset 的恢复目标。
- `readOnly` 不改变受控规则；它只把交互表面切换为静态 meter。非受控 readOnly 仍可由 `defaultValue` 与 form reset 恢复。
- reset 返回时原生 DOM/FormData 已同步恢复默认值，随后只同步 React 状态，不调用 `onChange`/`onChangeComplete`；取消 reset 时保持当前值。运行期改变 defaultValue 后，下一次 reset 使用最新默认值。
- 不支持在同一生命周期内切换受控性；遵循 React 表单控件约定。

## 数值、精度与边界

- 有限 min/max 先转为升序；非有限 min/max 分别回退 0/100。
- step 必须是正有限数，否则按 1；值以有效 min 为 step base，使用共享十进制算法对齐并最多保留 12 位，减少 `0.1 + 0.2` 漂移。max 不对齐时，原生 slider 的 max 也会收敛到最后一个可达步进值。
- 超界、NaN、Infinity 都会被规范化；`onChange` 报告与 DOM/视觉一致的值。
- min 等于 max 时进度为 0，控件没有可变范围；业务通常应改为只读文本。

## 表单集成

- 交互态透传 name、form、disabled、required、onInvalid 等原生属性；disabled 不进入 FormData。
- `readOnly` 使用 hidden input 提交当前规范值；`disabled + readOnly` 仍按 successful-control 规则不提交。HTML range 没有有效 readonly 语义，因此不会保留可调 slider 角色来伪装只读。
- range 总有浏览器值，HTML required 对“是否选择”没有业务校验意义；必须选择某一非默认业务值时由 schema/RHF 校验。
- Field 注入 label、description/error、invalid 和必填说明；组件不在不支持 `aria-required` 的 slider role 上伪造状态。
- ref 指向真实 range，可读取 `valueAsNumber`、`validity`、`form` 或调用 `focus()`。

## Props

完整表由 TypeScript/TSDoc 与 API Extractor生成。专有 Props：`defaultValue`、`value`、`min`、`max`、`step`、`marks`、`showValue`、`formatValue`、`readOnly`、`size`、`status`、`onChange`、`onChangeComplete`；其余来自原生 input（冲突字段除外）。

## Events

- `onChange(value, event)`：每次原生 range change 后触发，value 已规范化。
- `onChangeComplete(value, event)`：pointer up 或值变更键 keyup/blur 时，且本轮确有变化才触发；pointer cancel 不触发。
- 调用方的 pointer/keyboard/blur handlers 会保留。pointerdown 或 keydown 上 `preventDefault()` 可取消相应原生/内部交互启动。
- 受控父级拒绝新值时，change 仍按用户尝试报告；随后 DOM 由父级 value 回写。
- readOnly/disabled 不触发 change 或 complete。

## Ref 与命令式方法

交互态 ref 指向真实 `input[type="range"]`，可使用原生 `focus()`、`blur()`、validity 与 form API；readOnly 态 ref 指向参与 FormData 的 hidden input，不可聚焦。track、marks 和 value output 没有公开命令式句柄；程序化变值应更新受控 `value`，不要直接改 DOM value。

## 键盘操作

交互态原生支持 Arrow keys 按 step 调整、PageUp/PageDown 较大调整、Home/End 到边界。Tab 进入/离开。组件不重写浏览器键盘算法，只跟踪这些键来定义 complete 边界；屏幕阅读器组合键由平台保留。readOnly meter 不进入 Tab 路径。

## 触摸与手势

- 整条轨道最小高度 44px，thumb 为 20/22/24px；`touch-action: pan-y` 保留页面纵向滚动，横向调值依赖原生 pointer/touch 捕获并响应系统手势取消。
- 拖动期间 `onChange` 可高频触发；昂贵请求放在 `onChangeComplete` 或业务节流层。
- 组件不阻止页面纵向滚动，也不安装 document 级监听，适合 H5/WKWebView 嵌入。

## 无障碍

- 必须由 Field、`aria-label` 或 `aria-labelledby` 提供 accessible name；marks 和 output 不替代标签。
- 原生 slider 暴露 min/max/now；单位/语义值可用原生 `aria-valuetext`，视觉 `formatValue` 不会自动转成可访问文本。
- readOnly 用 meter 暴露 min/max/now/valuetext，并把装饰轨道从可访问树移除；Field 与调用方的 labelledby/describedby token 会合并去重，即使中间存在布局 wrapper 也不会丢失。
- error 使用 `aria-invalid` 并关联 Field error；disabled 使用原生属性。
- 无 Field/status error 时保留原生 range 上显式 `false/grammar/spelling` token；grammar/spelling 触发错误视觉，Field/status error 优先输出 `true`。
- output 不使用 aria-live，避免拖动时逐帧打断读屏。

## 动效

Slider 没有持续动画；数值变化直接更新 track。reduced-motion 不改变数值反馈，只缩短非必要状态过渡。

## 主题与定制

主题使用 accent/danger/surface/border/ink/muted 与尺寸 Token。forced-colors 下保留系统 Highlight/Canvas thumb 和系统
焦点；CSS gradient 仅作视觉增强，原生语义不依赖颜色。稳定入口为 size、status、marks、formatValue 与全局 Token。

## SSR 与 Next.js

- render 阶段不读取 window/document/layout；服务端输出确定的 range/value/output 或 meter/hidden value，effect 仅在客户端关联 form reset。独立 hydration 回归证明交互与只读节点不会被替换。

## RTL 与国际化

- 根与 input 接收 `dir`；RTL 下原生方向、渐变和逻辑 mark 定位反转。混合方向标签由调用方设置 lang/dir。

## 浏览器与 WebView

构建产物通过 Chrome 70 / iOS 13 语法基线。range 的 appearance、thumb pseudo-element、PageUp/PageDown 与 pointer
细节由浏览器实现；旧 WKWebView/Android WebView 仍需真机功能矩阵，语法通过不代表所有视觉和手势已验收。

## 边界情况与已知限制

- 仅单值、水平 slider；没有 range、vertical、tooltip、可点击 marks 或拖动前确认。
- readOnly ref 是 hidden input，不能用于 focus；静态可访问对象是外层 meter。
- `formatValue` 仅视觉；返回复杂交互节点会破坏 output 语义，不应这样使用。
- 不同浏览器对 PageUp/PageDown 的增量可能不同，这是原生契约。
- programmatic value 变化不触发 change/complete；业务副作用应监听自己的 state。

## 性能预算

无第三方运行时、布局测量、document listener 或持续 timer。拖动只做常数级数值规范化和一次状态/回调；复杂格式化函数由调用方自行 memo/控制成本。
