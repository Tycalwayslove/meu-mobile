# SearchField

## 当前能力

- 使用真实的 `input[type="search"]`，支持 ref、`name/form/autoComplete/inputMode` 等原生输入属性，以及受控和非受控值。
- 支持 Enter 搜索、IME 组合输入、clear、readOnly、disabled、loading、error 和三档高度；所有可操作目标至少 44×44 CSS px。
- `onChange/onClear/onSearch` 保留原有首参，并提供含稳定 `source` 与原始 React event 的 details 第二参。
- 有 `onSearch` 时组件独占 Enter 并阻止原生 form submit；没有 `onSearch` 时 Enter 完全交还原生 form。
- loading 时输入仍可编辑，但会隐藏 clear、公告搜索中状态，并阻止 Enter 产生重复回调或原生提交。
- 非受控值遵循原生 `form.reset()`，包括外部 `form=` 关联和可取消 reset；受控值始终由 `value` 决定。
- clear 获得键盘焦点后若被 loading 状态替换，焦点会回到输入，避免落到 document。
- 调用方与 Field 提供的全部 `aria-describedby` ID 会合并并去重，显式辅助说明不再覆盖 Field description/error。

当前状态为 `verification`。单元、SSR、Story play、本地 axe，以及 mobile Chromium/WebKit 的 Enter 搜索与清除路径已有证据；完整 Light/Dark 视觉审批、移动浏览器原生 form/details 专项、真机 IME 与读屏尚未完成，因此不能标记为 commercial。

## 何时使用

用于商城商品、订单、品牌或当前列表的文本搜索。适合“输入关键词后按 Enter 发起请求”以及“输入即过滤、Enter 确认”的场景。

## 何时不要使用

普通表单文本、地址或多行内容使用 `Input`/`TextArea`。筛选项很多时使用独立筛选页面；搜索建议、历史记录和结果浮层应由 Combobox/Popover 类模式组合，SearchField 本身不管理请求、列表或路由。

## 结构与状态

结构为 wrapper → 装饰性搜索图标 → native search input → clear button 或 loading status。状态包括 default、focus、error、read-only、disabled 与 loading。

- clear 只在 `clearable=true`、值非空、可编辑、非 loading、非 disabled 时出现。
- readOnly 保留焦点、复制与 Enter 搜索，但不允许改值或清空。
- disabled 使用原生 disabled，不能获得焦点或提交值。
- loading 不锁住输入编辑，方便用户修正查询；它只锁住提交动作。
- reset 不触发 `onChange/onClear/onSearch`；它恢复表单默认状态，而不是一次用户编辑。

## 基础用法

```tsx
const [query, setQuery] = useState("");

<SearchField
  aria-label="搜索商品"
  placeholder="商品、品牌或订单"
  value={query}
  onChange={(nextValue, details) => {
    setQuery(nextValue);
    analytics.track("search_value", { source: details.source });
  }}
  onSearch={(nextValue, details) => {
    void searchProducts(nextValue);
  }}
/>;
```

SearchField 不内置 debounce、请求取消、缓存、历史或路由同步。`onSearch` 是同步意图通知，不表示组件接管返回的 Promise。调用方应持有 AbortController，在新查询、清除或卸载时取消旧请求，并只让当前请求更新结果；请求期间传入 `loading`。

## 受控与非受控

传 `value` 时由调用方控制，组件只通过 `onChange(nextValue, details)` 请求更新；清除后如果调用方不更新 `value`，旧值仍会显示，原生 form reset 也不能改变它。只传 `defaultValue` 时组件拥有后续值，成功的原生 reset 会恢复当前 `defaultValue`，且不发布 change；被 `preventDefault()` 取消的 reset 保留当前值。不要在生命周期内切换受控模式。

## 表单集成

```tsx
<form
  action="/search"
  onSubmit={(event) => {
    // 这里是唯一请求入口；不要同时传 onSearch。
  }}
>
  <SearchField aria-label="搜索订单" name="query" />
</form>
```

- 未传 `onSearch`：Enter 保留浏览器原生 submit，适用于 Server Action、GET form 和统一 `onSubmit`。
- 传入 `onSearch`：Enter 先 `preventDefault()`，只调用 `onSearch`，不会再触发外围 form submit，避免一次按键发起两次请求。
- consumer `onKeyDown` 先执行；它调用 `preventDefault()` 后，SearchField 不再调用 `onSearch`。
- loading 或重复 Enter 会被阻止。disabled input 不参与 FormData；readOnly input 仍参与。
- 非受控 SearchField 支持祖先 form 和 `form="id"` 外部关联的 reset。reset 保持输入焦点，清除 IME 组合会话，不触发搜索或值事件。

如果旧代码故意同时依赖 `onSearch` 和 `onSubmit`，应迁移为单一入口。确需在回调中走 form 流程时，可显式调用目标 form 的 `requestSubmit()`，并确保只有一处发请求。

## Props

API 表由 `SearchFieldProps`、`SearchFieldSize`、`SearchFieldStatus` 与事件 details 类型生成。关键跨字段规则如下：

- `clearable` 默认 true；readOnly、disabled、loading 始终优先隐藏 clear。
- `defaultValue` 是非受控初值及原生 reset 的恢复值；`value` 是受控事实源。
- `enterKeyHint` 默认 `search`，只提示软键盘外观，不改变 Enter 所有权。
- `className/style` 作用在视觉 wrapper；`dir` 同时作用于 wrapper 与真实 input，使组件级 RTL 能翻转视觉顺序；其余原生 input 属性传给真实 input。内部 class 与 DOM 层级不是稳定 API。
- 显式 `aria-describedby` 会与 Field description/error 合并并去重；若业务确实需要替换 Field 文案，应在 Field 层调整，而不是依赖覆盖 ID。
- `clearLabel/loadingLabel` 可覆盖内置中英文 accessible name；未覆盖时跟随 `ConfigProvider.locale`。
- `status="error"`、Field error 或有效 `aria-invalid` 都进入 error 状态；无 contextual error 时 `false/grammar/spelling` 原样保留，Field/status error 优先输出 `true`。

## Events

| 事件        | 参数                      | source | 顺序与取消规则                                                                |
| ----------- | ------------------------- | ------ | ----------------------------------------------------------------------------- |
| `onChange`  | `(value, details)`        | input  | 原生 change 后更新非受控状态，再调用；`details.event` 是 input change event   |
| `onChange`  | `(value, details)`        | clear  | clear 请求空值后调用，随后恢复 input 焦点，再调用 `onClear`                   |
| `onClear`   | `(details)`               | clear  | 只由内置 clear button 触发；与同次 `onChange` 共用同一个 details/event        |
| `onSearch`  | `(value, details)`        | enter  | consumer keydown 未取消且非组合输入、非 repeat/loading 时触发；默认行为已阻止 |
| `onKeyDown` | 原生 React keyboard event | 不适用 | 总是先于 SearchField 的 Enter 逻辑；`preventDefault()` 可取消后续搜索         |

details 中的 `event` 是 React SyntheticEvent。单元测试直接断言 input、Enter 和 clear 的 `source` 与 event：clear 产生的 `onChange` 与 `onClear` 共享同一个 details 对象；这些 payload 尚未在移动 E2E 中采集。不要把 DOM event 序列化进日志；异步任务只保存需要的 value/source。

`onSearch` 是 Meu 的 Enter 意图回调，不等同于 WebKit 的非标准 DOM `search` event。组件不合成 Escape/cancel 的 native `search` 事件；未传 `onSearch` 时也不会拦截浏览器原生 search/form 行为。需要观察宿主特有 native `search` 事件时只能通过 ref 注册 DOM listener，并应把它视为平台适配而非跨浏览器契约。

## Ref 与命令式方法

ref 指向真实 `HTMLInputElement`，可调用 `focus()`、`blur()`、`select()`，读取 selection 和 `form`。内置 clear 在通知 `onClear` 前恢复 input 焦点，清空后的光标位于空值起点；loading 替换一个已聚焦的 clear 时同样恢复输入焦点。除测试和明确焦点恢复外，不要通过 ref 修改受控 value。

## 键盘操作

| 按键         | 行为                                                         |
| ------------ | ------------------------------------------------------------ |
| Tab          | 聚焦 input；值非空且可清除时，下一次 Tab 可聚焦 clear button |
| Enter        | 有 `onSearch` 时搜索；无 `onSearch` 时交给原生 form submit   |
| Enter (IME)  | 完成候选词，不触发搜索                                       |
| Enter repeat | 阻止重复搜索和重复原生提交                                   |
| Space        | clear button 聚焦时按原生 button 规则清空                    |

浏览器对 `input[type="search"]` 的 Escape 行为并不一致，Escape 清空不属于当前公开契约；使用内置 clear button 可获得一致事件和焦点行为。

SearchField 不内置“退出搜索模式”的 cancel action。移动页面若需要“取消”，应在 SearchField 外放置有明确文案的原生 button，由页面负责清空、关闭建议层或返回上一页；不要把这些不同业务语义压缩成 Escape。

## 触摸与手势

没有自定义手势。输入区高度与 clear button 均至少 44 CSS px；clear 使用原生 button，tap 后重新聚焦输入，鼠标按下不会先夺走焦点。组件不拦截页面滚动、不注册全局 pointer listener，也不自行 debounce 快速输入。

## 无障碍

输入使用原生 searchbox 语义，必须通过 `Field label`、`aria-label` 或有效 `aria-labelledby` 获得名称。搜索图标为装饰内容。clear 是有名称的原生 button；loading 插入 `role="status"` 并在 input 设置 `aria-busy`，避免 busy 容器延迟状态公告。error 通过 `aria-invalid` 以及 Field 的 description/error 关联表达，不能只看边框颜色。

调用方 `aria-describedby`、Field description 与 Field error 会组合而不是相互覆盖，并过滤重复 ID。这样外部搜索策略、字段帮助和当前错误能同时被读屏获得。

ARIA invalid token 只位于原生 searchbox，不复制到图标、clear 或 loading status。`grammar/spelling` 触发错误视觉但保持原 token；显式 `false` 在无 Field/status error 时保持为 `false`。

内置中文/英文 clear 和 loading 名称只覆盖现有 locale；其他语言必须传 `clearLabel/loadingLabel`。当前尚未留下 VoiceOver/TalkBack 与 200% 字号证据。

## 动效

焦点、背景和边框过渡使用共享 motion token。loading ring 只在任务进行中旋转；`prefers-reduced-motion: reduce` 时完全停止并保留静态缺口 ring，状态仍通过 `role=status` 和 `aria-busy` 表达。没有永久装饰性动画。

## 主题与定制

颜色、圆角、尺寸和 motion 只引用 Meu 语义 Token。稳定定制入口为 size、status、原生属性、`className/style` 以及 `data-size/data-state/data-readonly`。内部 vanilla-extract class、icon 和 wrapper 层级不是公开 API。

## SSR 与 Next.js

渲染不读取 window/document，SSR 单测证明会输出真实 search input、name、value、readOnly、loading 与 disabled 状态。独立 `hydrateRoot` 测试以相同 props 完成 hydration，断言没有 mismatch，且 hydration 后 clear、值更新和焦点恢复仍可用。服务端与首次客户端故意使用不同 `value/defaultValue/loading/readOnly` 仍属于调用方 mismatch，不由组件掩盖。组件包含 `"use client"`，应从 Next Client Component 使用。

## RTL 与国际化

布局使用 `padding-inline`，会跟随上层 `dir`；显式传给组件的 `dir` 同时设置在 wrapper 和 input，保证图标/操作顺序与文本方向一致。搜索和 clear 图标本身对称，不需要镜像。业务 placeholder、label 和请求结果文案由调用方本地化；内置 clear/loading 名称可覆盖。

RTL Story 提供阿拉伯语与 `dir=rtl` 的人工/自动检查入口；阿拉伯语 IME、混合双向长文本和系统字体放大仍缺真机证据。

## 浏览器与 WebView

实现使用原生 input/button、Flex、CSS logical properties、`:focus-within`、native click、基础 key/composition events 和 `setTimeout`，没有依赖超出 Chrome/WebView 70 与 iOS 13 的强制运行时 API。输入使用 16px 字号并关闭 WebKit 原生 search 外观，避免 iOS 聚焦自动缩放与宿主装饰覆盖内建 clear。`enterKeyHint` 在不识别它的旧宿主中仅作为无害属性，不影响硬键盘 Enter 或 form submit。静态兼容和 jsdom 证据不等于真机运行时证明，Chrome 70 与 iOS 13 仍需目标宿主回归。

待补 iOS 中文输入法、Android Gboard、WKWebView 软键盘 `enterKeyHint`、VoiceOver/TalkBack 和 tap-clear 键盘保持的真机记录。

## 边界情况与已知限制

- 组件不 trim、规范化或限制关键词；空字符串是否可搜索由业务决定。
- loading 允许继续编辑，但阻止 Enter；业务需要在 query 改变时取消或忽略旧请求。
- disabled/readOnly/loading 的切换不会取消业务请求；SearchField 没有请求句柄，取消必须由调用方持有。
- clear 是值变更请求，不保证受控调用方接受空值。
- `onSearch` 现在阻止外围 form submit；依赖旧“双触发”行为的代码必须迁移到单一请求入口。
- IME 通过 composition state、blur reset、native `isComposing` 与兼容性 `keyCode=229` 防护，但仍需真机输入法矩阵。
- 浏览器原生 search Escape/cancel 行为不作为契约；WebKit cancel 按钮被隐藏以避免绕过 `onClear`。
- `className/style` 历史上作用于 wrapper，而非原生 input；修改该行为会是破坏性变更。

## 性能预算

每个实例维护一个非受控 value state、composition ref 与 reset timer ref。组件在 input 的 `ownerDocument` 注册一个 reset 委托 listener，并核对 `event.target === input.form`；因此外部 owner 可晚挂载或同 id 替换，且无关表单不会触发同步。listener 与 timer 在卸载时清理。每次输入只产生一次本地更新和调用方回调；请求、防抖与竞态取消由业务层负责。
