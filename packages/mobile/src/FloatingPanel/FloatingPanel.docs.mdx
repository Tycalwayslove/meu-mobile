# FloatingPanel

## 当前能力

- 常驻、非模态的顶部或底部浮动面板；不创建 Mask、Portal、滚动锁或焦点圈定。
- 正像素 anchors 会过滤、排序、去重并夹紧至 44px–visual viewport；支持受控/非受控高度。
- 原生 44px handle 支持拖拽、点击、方向键、PageUp/PageDown、Home/End；非交互内容只辅助向更高 anchor 展开。
- 有限速度投影；pointer cancel/lost capture、拖拽配置变化和卸载会清理临时拖拽状态。

## 何时使用

用于地图详情、行程卡片、筛选摘要等必须持续保留背景上下文的 modeless 页面。

## 何时不要使用

需要遮罩、关闭、焦点管理或背景不可交互时使用 BottomSheet/Dialog；普通页面区块不要固定到视口。

## 结构与状态

panel → handle button → scrollable body → visually hidden status。状态包括 measured、anchor index、dragging、disabled、immediate，以及 top/bottom placement。

## 基础用法

```tsx
<FloatingPanel anchors={[180, 360, 620]} defaultHeight={180}>
  <RouteDetails />
</FloatingPanel>
```

## 受控与非受控

`height` 存在即受控；交互只调用 `onHeightChange`，调用方未提交新值时仍以原值为准。非受控使用 `defaultHeight`。任意请求值映射到最近的归一化 anchor。

## 表单集成

不适用。面板高度不是业务字段，也不进入 FormData。

## Props

API 表由 `FloatingPanelProps` 生成。`anchors` 是物理像素高度；`placement` 是物理边。空值、非有限值和非正 anchor 被忽略，最终无有效 anchor 时使用视口高度的一半。

## Events

`onHeightChange(height, { index, reason })` 在请求不同 anchor 时同步触发；reason 为 `drag | handle | keyboard | imperative`。事件不可取消；受控调用方通过不更新 `height` 拒绝请求。

## Ref 与命令式方法

`nativeElement` 指向根节点；`setHeight(height, { immediate })` 请求最近 anchor。disabled 时命令式请求同样被忽略。

## 键盘操作

| 按键                 | 行为                          |
| -------------------- | ----------------------------- |
| Enter / Space        | handle 循环到下一个 anchor    |
| Home / End           | 最低 / 最高 anchor            |
| ArrowUp / PageUp     | bottom 面板升高；top 面板降低 |
| ArrowDown / PageDown | bottom 面板降低；top 面板升高 |

## 触摸与手势

handle 在 6px 后锁定纵向，横向意图取消；pointer capture 获取失败时临时监听 window，丢失 capture 或 cancel 会回滚，所有兜底监听在结束、配置变化或卸载时清理。anchors、placement、disabled 或 `dragFromContent` 在拖拽中改变会取消旧手势。内容区只在低于最高 anchor、起点非交互元素时接管向展开方向的拖拽；原生控件、可聚焦节点、常见 ARIA widget 与带 `data-meu-floating-panel-drag-ignore` 的区域不会被接管，收起始终使用 handle。速度阈值 0.5px/ms，投影由 `inertiaFactor` 限制在 0–200ms。

## 无障碍

handle 是具名原生 button，关联 body 与实时高度说明；disabled 或归一化后不足两个 anchor 时使用原生 disabled，避免暴露无效操作。面板不宣称 dialog，也不移动、圈定或恢复焦点。

## 动效

高度由 transform 过渡；拖拽与 `immediate` 请求期间关闭过渡。reduced-motion 将过渡压缩到 1ms，中断时回到权威 anchor。

## 主题与定制

稳定入口为全局颜色、圆角、阴影、motion、安全区 Token 和根 `style/className`。内部 class/CSS 变量不是公开 API。forced-colors 保留 handle 边界。

## SSR 与 Next.js

组件是 client component。服务端输出确定的 50vh 隐藏 shell；挂载后读取 visual viewport、归一化 anchors 再显示，避免未测量位置闪现。anchors、placement 和 children 在 hydration 前必须稳定。

## RTL 与国际化

垂直手势不随 RTL 反转。内置中英文 handle/status 文案，业务可用 `handleLabel` 覆盖。top/bottom 是物理方向。

## 浏览器与 WebView

完整运行时支持档与仓库总矩阵一致：Android Chrome/WebView 89+、iOS Safari/WKWebView 15+。Chromium/WebView 79–88 与 iOS 13–14 仅属观察档，Chrome 70 只做构建产物静态语法扫描，不构成运行时承诺。visualViewport 缺失时退回 innerHeight，pointer capture 缺失或抛错可降级；尚无目标 App 真机证明。

## 边界情况与已知限制

- 不支持百分比/content anchor、弹簧、dismiss、嵌套面板或背景滚动锁。
- 内容拖拽只展开；到最高 anchor 后完全交给原生滚动。
- visual viewport resize 会重新夹紧 anchors，不伪造变更事件。

## 性能预算

拖拽只更新一个 transform 状态；anchors 应保持小数组。复杂 body 的渲染和列表虚拟化归调用方。

## 测试证据

- Unit/SSR: 2 个文件共 21 tests，覆盖归一化、单 anchor 禁用、受控、速度/方向锁、capture fallback、配置与 visual viewport 变化取消、交互内容边界、原生根事件、键盘、ref 和确定 SSR shell。
- Story interaction: `Bottom` 验证 handle 点击与锚点状态变化；`check-storybook-links` 已验证全库 81/81 title 各至少一项关键 play，本 title 的 play 在本地扫描中返回 `storyFinished=success`。
- Storybook 浏览器矩阵：本地扫描器在 390×844 视口验证 444 个 Story × 7 场景（Light、Dark、en-US、RTL、reduced-motion、200% 字体、forced-colors），共 3,108 个组合；有 play 的 Story 必须先返回 `storyFinished=success`，再运行 axe WCAG A/AA，结果为 0 违规、0 `pageerror`。
- 官网 Next 运行时：本地 production build 在 390×844 下逐页验证 68 个组件页的 Light/Dark（136 场景）；主题恢复、H1/预览/API 结构、React `pageerror` / `console.error`（含 hydration mismatch）和 axe WCAG A/AA 均通过。
- Bundle：Rollup tree-shaken ESM（React 与包 peer dependencies external）单一公开值 gzip 5591 B / 32768 B 预算，组合 Brotli 4960 B；共享样式由应用单独导入一次。
- SSR/hydration: `FloatingPanel.ssr.test.tsx` 在 Node 覆盖确定 shell；隔离 Next production 的 Chromium/WebKit 聚合检查确认组件已挂载且无 `pageerror` / `console.error`，尚未单独断言服务端根节点复用、`data-measured` 或初始 300px 高度。
- RTL: 垂直方向不适用；排版矩阵待补。
- Reduced motion: CSS 契约已实现，浏览器断言待补。
- Mobile Chromium/WebKit E2E: 键盘 snap、合成 pointer 拖动、最高点的内容拖拽标记移交和受控高度输出均通过；另与 SwipeActions 组合执行 40 轮 pointercancel 后再次完成有效拖拽，确认无残留 dragging 状态，组合同步成本 ≤1,000ms，两种引擎各重复 3 轮通过。尚未用真实 touch、60 秒帧率或 `scrollTop` 断言原生滚动恢复。
- Chromatic Light/Dark: stories 可采集，正式基线待确认。
- Real device: 待补。
