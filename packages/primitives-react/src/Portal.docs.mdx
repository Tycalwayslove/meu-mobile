# Portal

## 当前能力

- 默认把内容渲染到当前文档的 `document.body`。
- `container` 支持 `Element`、`DocumentFragment`、惰性回调、`null` 和 `undefined`。
- SSR 与 hydration 首帧原地输出 children，客户端可用后再移动到目标容器。
- 目标变化或组件卸载时，由 React Portal 删除其渲染节点；组件不会删除调用方拥有的容器。
- 容器判断基于 DOM `nodeType`，可接受 iframe 等其他 realm 的 Element，不依赖 `instanceof HTMLElement`。
- 惰性 resolver 首次客户端渲染为空时，会在 ref 提交后补一次同步重试，支持同次提交的 ref-backed 容器。
- React Context 与合成事件沿逻辑 React 树保持连接；跨 Document 目标不会切断 Provider 数据或 React 事件冒泡。
- 同页归档两个公开 Overlay Hook：`useBodyScrollLock` 使用引用计数锁定 body 并按 LTR/RTL 补偿滚动条；`useFocusTrap` 只让栈顶模态圈定焦点，支持初始焦点、Escape、焦点分支与恢复。

本地自动化已经完成真实同源 iframe/跨 Document、嵌套模态和移动 Chromium/WebKit 验收。当前状态仍为 `verification`；真实 iOS/Android WebView、读屏浏览模式与 Chromatic 基线审批尚未完成，不能标记为 commercial。

## 何时使用

用于 Popup、Dialog、Toast 等需要脱离祖先 `overflow` 或 stacking context 的浮层。优先复用一个由应用管理的稳定浮层根节点。

## 何时不要使用

- 普通页面内容、布局组件和无需脱离 DOM 层级的提示不需要 Portal。
- 不用 Portal 代替焦点管理、遮罩、滚动锁或 z-index 规范。
- 不要把敏感内容是否服务端输出的决策交给 Portal；它在 SSR 会原地保留 children。

## 结构与状态

Portal 不新增包装 DOM。结构只有 React children 和解析后的目标容器。运行状态为 SSR 原地、客户端 body、自定义目标和显式原地四种；两个 Hook 分别维护进程内 body lock token 集合与 focus-trap 栈。

## 基础用法

```tsx
<Portal>
  <div role="status">保存成功</div>
</Portal>
```

自定义容器应在可用后传入：

```tsx
const [overlayRoot, setOverlayRoot] = useState<HTMLDivElement | null>(null);

return (
  <>
    <div ref={setOverlayRoot} />
    {overlayRoot ? <Portal container={overlayRoot}>浮层内容</Portal> : null}
  </>
);
```

## 受控与非受控

不适用。Portal 不持有打开状态；挂载、卸载和目标容器均由调用方控制。

## 表单集成

Portal 不改变 React 树关系，因此 context 与 React 合成事件仍沿逻辑树工作，包括跨 Document 目标。但原生 DOM 查询、原生事件、`form` 所属关系和 CSS 继承取决于实际目标；跨出表单时，提交按钮应显式设置 `form` 属性。

## Props

`children` 为渲染内容。`container` 未传时使用 `document.body`；传 `null` 时保持原地；回调只在客户端可用后解析。API 类型以 TSDoc/API Extractor 为准。

resolver 在客户端 render 中读取；若首次返回空值，Portal 会在 refs 挂载后的 layout 阶段重试一次。resolver 必须无副作用并返回稳定容器；后续目标变化仍需由调用方触发 React render。

`useBodyScrollLock(locked)` 的布尔值决定当前实例是否持有锁。`useFocusTrap(options)` 接受 `active`、`containerRef`、可选 `initialFocusRef`、`returnFocusRef`、`onEscape` 与 `restoreFocus`。

## Events

不定义事件。children 的 React 事件按 React Portal 规则沿逻辑 React 树冒泡；原生事件监听仍遵循实际 DOM 树。

## Ref 与命令式方法

不适用。Portal 没有包装节点，因而不提供 ref 或命令式方法。需要访问内容节点时由 child 自己持有 ref。

## 键盘操作

| 按键            | 行为                                                                                                  |
| --------------- | ----------------------------------------------------------------------------------------------------- |
| Tab / Shift+Tab | Portal 本身不处理；`useFocusTrap` 在栈顶容器与可操作 Toast 间循环；显式 focus branch 保留自身键盘路径 |
| Escape          | Portal 本身不处理；栈顶 trap 调用最新 `onEscape`                                                      |
| 其他            | 交由 children                                                                                         |

## 触摸与手势

不定义触摸或手势。点击外部关闭、拖拽、手势冲突和 pointer capture 由上层浮层组件负责。

## 无障碍

Portal 不提供 role 或 accessible name。`useFocusTrap` 按原生 Tab 顺序过滤 `tabIndex<0`、disabled/disabled fieldset、非选中 radio、hidden、aria-hidden、inert、display:none 与 visibility:hidden 后代，容器无可聚焦项时聚焦容器。激活时共享管理器会把顶层模态之外的 siblings 设为 inert/aria-hidden，嵌套关闭后按引用计数恢复原属性；focus branch、由模态内 `aria-controls` 关联的非模态浮层和 Toast live region 保持可达。可操作 Toast 会加入栈顶模态的键盘循环，因此模态期间出现的撤销/重试按钮不会成为视觉可见但键盘不可达的孤岛。

## 动效

不适用。Portal 只负责挂载位置。进入/退出动画必须由上层组件控制，并在退出动画完成后再卸载。

## 主题与定制

Portal 没有 Token 或内部 class。渲染到 `body` 或另一个 Document 后，祖先 CSS 变量可能不再继承；应用应把 Meu 主题变量安装到目标容器或目标文档。

## SSR 与 Next.js

文件声明为 Client Component。服务端及 hydration 首帧会原地渲染 children，避免读取 `document` 和空 SSR 标记；因此 open overlay 会先出现在调用位置，客户端 store 快照可用后再移动到 body 或自定义 target。若 JavaScript 被禁用，这些 children 会一直保留在调用位置，Portal 不会完成移动或提供交互初始化。若浮层不应进入服务端 HTML，调用方应在业务层按 open/client-ready 条件控制 children。

## RTL 与国际化

不适用。Portal 不生成文案或方向样式；目标容器的 `dir`、`lang` 和主题继承可能与逻辑父级不同，跨容器时应显式同步。

## 浏览器与 WebView

实现使用 React 19 Portal、`useSyncExternalStore`、Element/DocumentFragment 和 `nodeType`，源码未引入 Chrome 70 禁止语法。跨 realm 容器不再依赖 `instanceof HTMLElement`。同源 iframe 已在桌面宿主的移动 Chromium/WebKit 项目中自动验证；真实 iOS 13 WKWebView 与 Android Chrome 70 仍待设备验证。

## 边界情况与已知限制

- 容器回调在客户端 render 时执行，必须无副作用且返回稳定 DOM 节点；首次为空时会在同次提交的 refs 挂载后同步重试一次。
- 回调在重试后仍返回空、显式 `null` 或非法运行时对象时内容原地渲染。
- 已移出 Document 的目标不会被组件自动替换；调用方需更新 `container` 并触发 render。
- React 只清理 Portal children，不删除或还原调用方的目标容器。
- 跨 Document 不会自动复制样式、方向、locale 或全局事件监听。
- `useBodyScrollLock` 和 `useFocusTrap` 使用当前 realm 的全局 document/window，不支持跨 Document 管理。
- modal isolation 识别 `[data-meu-overlay-layer]`、`[data-meu-focus-branch]` 和 `aria-controls` 关系；自定义第三方 Portal 若不提供这些关联，需要由宿主放在模态 DOM 分支内。

## 性能预算

Portal 本身不创建 DOM wrapper、observer、timer 或全局监听。只有首次 ref-backed resolver 返回空值时增加一次提交后重渲染；激活的 `useFocusTrap` 维护一个共享 MutationObserver，只在 body 子树增删 Portal 分支时重新计算顶层模态隔离；容器回调不得包含布局扫描。

- Unit: `Portal.test.tsx` 覆盖默认/惰性/Fragment/原地目标、ref-backed 提交后重试、目标切换、卸载清理、SSR resolver 隔离、hydration recoverable error，以及真实 iframe `contentDocument` 中的 ownerDocument、Context、合成事件与精确清理；`overlayHooks.test.tsx` 覆盖嵌套滚动锁、RTL 补偿、栈顶 Escape、原生 tabbable 顺序、可操作 Toast 键盘分支、背景 inert/aria-hidden 隔离与精确恢复。
- Story interaction: `CustomContainer` 验证内容移动到调用方提供的目标容器；`LazyRefContainer` 验证同次提交 ref-backed resolver；`CrossDocument` 在真实 iframe Document 中验证 ownerDocument、Provider Context 与逻辑 React 事件冒泡。
- 本次定向 Storybook 扫描：Portal 3 个 Story × Light/Dark，共 6 个场景，play 与 axe WCAG A/AA 均通过。
- Storybook 浏览器矩阵：本地扫描器在 390×844 视口验证 444 个 Story × 7 场景（Light、Dark、en-US、RTL、reduced-motion、200% 字体、forced-colors），共 3,108 个组合；有 play 的 Story 必须先返回 `storyFinished=success`，再运行 axe WCAG A/AA，结果为 0 违规、0 `pageerror`。
- 官网 Next 运行时：本地 production build 在 390×844 下逐页验证 68 个组件页的 Light/Dark（136 场景）；主题恢复、H1/预览/API 结构、React `pageerror` / `console.error`（含 hydration mismatch）和 axe WCAG A/AA 均通过。
- Bundle：Rollup tree-shaken ESM（React 与包 peer dependencies external）3 个公开值组合 gzip 4426 B / 32768 B 预算；最大单值 `useFocusTrap` 为 3012 B / 32768 B 预算，组合 Brotli 3840 B；共享样式由应用单独导入一次。
- SSR/hydration: `Portal.test.tsx` 覆盖服务端原地标记、SSR 不执行 resolver、hydration 后移动和零 recoverable error；Next 专项直接读取 production 响应确认 Portal child 与 Provider 值存在于服务端 HTML，再验证 hydration 后移入 iframe
- RTL: 无视觉方向逻辑；跨容器 `dir` 同步待 E2E
- Reduced motion: 不适用，无动画
- Mobile Chromium/WebKit E2E: `composes layout, icon action, custom portal and hidden accessible text` 在两种引擎断言 hydration 后内容位于调用方 custom container；独立 `overlay-lifecycle.spec.ts` 通过 Popup 组合验证打开时切换目标不会留下重复 Portal children，退出中断后旧 presence timer 不会误删重开的内容，并保持单一焦点圈定与 body lock；`portal-cross-document.spec.ts` 的两项契约在两种引擎共 4/4 通过，覆盖真实 iframe container/ownerDocument、Provider、React 与原生事件边界、焦点、目标切换、卸载只清 child、保留调用方 target 与重新挂载
- Chromatic Light/Dark: 已有 CustomContainer Story，更新基线待 CI 发布
- Real device: 待补
